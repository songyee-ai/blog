## 한 줄 정의

> 프로그램이 정해 둔 순간에 이르면, 미리 걸어 둔 내 명령이 저절로 실행되게 하는 연결 고리

---

## 1. 비유로 이해하기

받아쓰기 시간이다. 선생님은 아이들이 쓰는 동안에는 공책을 들여다보지 않는다. 대신 규칙이 하나 있다. "다 쓴 사람은 공책을 덮기 전에 선생님한테 보여 줄 것." 아이가 "다 했어요" 하고 공책을 들고 오면 선생님이 한 번 본다. 괜찮으면 "덮어도 돼." 틀린 줄이 있으면 "셋째 줄 다시 써 와" 하고 공책을 돌려준다. 아이는 자리로 돌아가 그 줄을 고쳐 쓴다.

이 규칙은 쓰는 도중에는 아무 일도 하지 않는다. "다 했어요"라고 말하는 그 순간에만 움직인다. 그리고 선생님이 보기 전에 짝꿍이 공책을 이미 봤다면, 짝꿍이 본 틀린 글씨까지 되돌릴 수는 없다.

그래서 실제로는, 훅은 **프로그램이 정해 둔 순간마다 저절로 불리는 내 명령**이다. Claude Code의 Stop 훅은 Claude가 답을 마치려는 순간에 내가 등록한 스크립트를 실행한다. 스크립트가 "막는다"고 답하면 그 이유가 Claude에게 돌아가고, Claude는 그 이유를 읽고 이어서 작업한다.

## 2. 왜 필요한가

### 규칙을 "부탁"이 아니라 "검사"로 바꾼다

나는 "사용자에게 보이는 글은 한국어로"라는 규칙을 `CLAUDE.md`에 적어 두고 Claude Code를 쓴다. 그런데 깃·PR·배포처럼 영어 출력이 많은 작업을 길게 이어 가면 답이 영어로 나오는 일이 있었다. 대화 기록을 다시 보면, 규칙을 메모리 지침에 적은 지 10분 뒤에도 다시 영어 답이 나왔다. 규칙 파일은 모델이 읽고 따라 주기를 바라는 글이다. 그래서 답을 마칠 때마다 영어 문장을 세어, 많으면 되돌려 보내는 Stop 훅을 만들었다. 훅은 모델이 실행할지 말지 고르는 것이 아니라 Claude Code가 그 순간마다 실행한다.

### 설정 파일에 "언제, 무엇을"을 적어 건다

훅은 설정 파일에 {% include term.html name="JSON" %}으로 적는다. 과제 실험의 실행 스크립트 `run_one.sh`가 훅을 켠 조건에서 만드는 설정은 이런 모양이다(경로는 줄였다).

```json
{
  "hooks": {
    "Stop": [
      { "hooks": [
          { "type": "command",
            "command": "python3 scripts/korean_guard.py",
            "timeout": 10 }
      ] }
    ]
  }
}
```

`"Stop"`이 **언제**(답을 마치려 할 때), `"command"`가 **무엇을**(이 파이썬 스크립트를 실행)이다. 훅을 끈 조건은 `{"hooks": {}}` 하나만 둔 설정이다. 두 설정을 `claude -p ... --settings <설정 파일>`로 번갈아 걸어서, 훅 말고는 같은 조건으로 실행했다.

### 막을 때는 이유를 함께 돌려준다

훅 스크립트는 판정한 결과를 다시 JSON으로 내놓는다. 막을 때는 이렇게 쓴다(이유 문장은 줄였다).

```json
{"decision": "block", "reason": "이번 답에 영어 문장이 섞여 있다 (영어 줄 2개 …). 방금 답을 한국어로 다시 써라."}
```

`reason`에 적은 글이 모델에게 돌아가고, 모델은 그것을 읽고 이어 쓴다. 내 훅의 기준은 "한글 없이 영어 낱말 7개 이상인 줄이 2줄 이상이거나, 글 전체에서 영문자가 60자를 넘고 한글이 영문자의 0.6배보다 적으면 막는다"이다. 코드·경로·주소는 세지 않는다. 그리고 훅 입력에 `stop_hook_active`가 켜져 있으면, 즉 이미 한 번 돌려보낸 뒤라면 막지 않는다. 그러지 않으면 "다시 써라 → 다시 썼다 → 다시 써라"가 끝없이 돌 수 있다.

### 훅이 보는 것은 상황마다 다를 수 있다

훅은 Claude Code가 넘겨주는 정보를 보고 판단한다. 내 훅은 처음에 세션 기록 파일에서 마지막 답을 찾아 읽었다. 그런데 비대화형(`claude -p`)으로 돌리니 훅이 실행되는 순간에는 마지막 답이 아직 기록 파일에 들어 있지 않았고, 고치기 전에는 영어 답을 막지 못했다. 그래서 훅 입력에 함께 들어오는 `last_assistant_message`를 덧붙여 판정하게 고쳤다. 같은 훅이라도 실행하는 방식이 바뀌면 보이는 것이 달라질 수 있다.

## 3. 어디서 만났나

**25회차** 노드 11 과제에서 "자기 도구의 불편을 가설로 바꿔 실험하기"를 하면서 다뤘다. 나는 이미 쓰고 있던 Stop 훅이 정말 효과가 있는지를 주제로 골랐다. 훅을 켠 조건과 끈 조건을 세 번씩 번갈아 돌렸고, 훅을 켠 세 번에서 훅은 요청마다 한 번씩 모두 30번 실행됐다. 되돌려 보낸 적은 한 번도 없었고, 훅을 끈 기준선에서도 영어 답이 0건이라 결과는 판정 불가였다. 실험 보고서에서는 이 훅을 하네스 기능 가운데 평가 루프와 성찰에 해당하는 장치로 적었다.

## 4. 헷갈리는 개념

| 이 용어 | 비슷하지만 다른 것 | 차이 |
| --- | --- | --- |
| Claude Code 훅 | React 훅 | React 훅(`useState` 같은 것)은 화면을 만드는 코드 **안에서 부르는 함수**로, 컴포넌트가 상태를 기억하게 해 준다. 정해진 순간에 밖에서 걸어 둔 명령이 도는 것이 아니다. 이름만 같다 |
| Claude Code 훅 | git 훅 | git 훅은 커밋·푸시 같은 **깃 동작** 직전이나 직후에 도는 스크립트다(`.git/hooks/` 안의 `pre-commit` 등). "정해진 순간에 내 스크립트"라는 생각은 같지만, 걸리는 프로그램과 순간이 다르다 |
| 훅 | {% include term.html name="트리거" %} | 트리거는 워크플로를 **시작하게 하는** 신호다. 훅은 이미 돌고 있는 프로그램의 **정해진 순간에 끼어든다** |
| 훅 | `CLAUDE.md` 규칙 | 규칙은 모델이 읽고 **따르기를 바라는 글**이다. 훅은 Claude Code가 그 순간마다 **반드시 실행하는 프로그램**이다 |

## 5. 많이들 오해하는 지점

**ㄱ. "Stop 훅을 걸면 영어가 새지 않는다"**

Stop 훅은 답을 **다 쓴 뒤에** 검사한다. 쓰는 동안 화면에 나간 글은 이미 나간 것이다. 실험을 준비하던 실제 세션에서 도구 사이 진행 문장 한 줄이 영어로 나왔는데, 한 줄이라 그 자리에서는 막히지 않았다. 나중에 다른 한 줄이 같은 검사 범위에 쌓였을 때 "영어 줄 2개"로 처음 막혔고, 그때는 첫 줄이 화면에 나간 지 약 50분 뒤였다. 답한 뒤 검사는 새는 것을 막는 장치가 아니라, 나중에 바로잡는 장치다.

**ㄴ. "훅이 한 번도 막지 않았으니 쓸모가 없다"**

내 실험에서 훅은 30번 실행되고 0번 막았다. 하지만 훅을 끈 쪽에서도 영어 답이 0건이었다. 막을 것이 애초에 없었으니 "효과가 있다"도 "효과가 없다"도 말할 수 없다. 훅을 켠 시도 가운데 두 번은 도구 사이에 영어 한 줄이 나왔고 훅은 통과시켰다. 이것도 고장이 아니라 "2줄부터 막는다"는 문턱이 정한 대로 움직인 것이다. 0번 막았다는 숫자는 훅의 효과보다 실험 길이와 문턱에 대해 더 많이 알려 준다.

**ㄷ. "훅 비용은 크다 — 막을 때마다 다시 쓰니까"**

되돌려 보내면 모델이 긴 기록을 다시 읽고 답을 다시 쓰니 토큰과 시간이 늘 수 있다. 나도 실험 전에 훅을 켜면 토큰과 시간이 10~30% 늘 것이라고 예상했다. 실제로는 되돌린 적이 없어서 훅의 비용은 스크립트 실행 수십 밀리초뿐이었다. 훅을 켠 쪽 토큰이 오히려 9% 적었는데, 시도끼리의 차이가 이보다 커서 훅 때문이라고 볼 수 없다. 훅 비용은 "걸었느냐"보다 "얼마나 자주 막느냐"에 달려 있다.
