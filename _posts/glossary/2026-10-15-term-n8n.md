## 한 줄 정의

> 할 일 칸(노드)을 화살표로 이어 그리면 그 순서대로 실행해 주고, 칸마다 주고받은 값을 기록으로 남기는 워크플로 자동화 도구

---

## 1. 비유로 이해하기

책상 위에 **도미노**를 세운다고 해 보자. 어느 블록 다음에 어느 블록이 넘어질지는 세우는 사람이 미리 정한다. 갈림길을 만들어 두면 한쪽 줄만 넘어가게 할 수도 있다. 다 세운 뒤 첫 블록을 손가락으로 톡 밀면, 그다음부터는 사람이 손대지 않아도 정해 둔 길을 따라 차례로 넘어간다.

여기에 하나를 더한다. 도미노 판 위에 **카메라**를 달아 두는 것이다. 중간에 한 블록이 안 넘어가고 멈췄다면, 영상을 돌려 보면서 몇 번째 블록에서 무엇 때문에 멈췄는지 찾을 수 있다.

{% include figure.html src="/assets/images/term-n8n/build-run-record.svg" alt="위쪽에 워크플로를 만드는 두 길을 나란히 그렸다. 왼쪽은 화면에서 노드(칸)를 끌어다 놓고 연결선으로 잇는 길, 오른쪽은 코딩 에이전트가 wf.json을 먼저 보여 주고 확인받은 뒤 n8n-cli workflow create로 만드는 길이다. 두 길 모두 가운데의 n8n 워크플로로 이어진다. 워크플로는 Manual Trigger 칸에서 HTTP Request 칸(위키백과 공개 요약 읽기)으로 화살표가 이어지고, 실행은 화면의 Execute workflow 버튼으로 한다. CLI에는 새 실행을 시작하는 명령이 없다. 맨 아래에는 한 번 실행할 때마다 실행 기록 1건이 남고, 칸마다 상태 코드와 원본 응답이 남으며, 화면의 Executions 탭이나 CLI의 execution list, get으로 다시 꺼낸다고 적었다" caption="그림 1. 만드는 길은 두 갈래지만, 순서는 그래프가 정하고 실행마다 기록이 남는다" %}

그래서 실제로는, n8n에서 도미노 블록 하나하나가 **노드(그래프의 칸)**다. 이 블로그에서 "노드"는 보통 수업 자료의 단원을 가리키지만, n8n 이야기에서는 "할 일 하나를 맡은 칸"을 뜻한다. 첫 블록을 미는 손가락이 {% include term.html name="트리거" %}, 블록을 세운 길이 연결선, 완성된 판 전체가 {% include term.html name="워크플로" %}다. 카메라 영상에 해당하는 것이 **실행 기록(Executions)**이다. 실행할 때마다 어느 칸이 무엇을 받아서 무엇을 내보냈는지가 한 건씩 남는다.

## 2. 왜 필요한가

### 흐름이 눈에 보여야 고칠 수 있다

메일을 읽고, 내용을 나누고, 담당자에게 알리는 일을 코드로 짜 두면 순서가 코드 속에 숨는다. 무언가 잘못돼도 어디서 틀렸는지 찾으려면 코드를 읽어야 한다. n8n은 같은 흐름을 **화면에 그림으로** 둔다. 그린 그림이 곧 실행되는 순서라서, 화면을 보면 지금 어떤 길로 일이 흘러가는지 바로 보인다.

원래 이름은 **nodemation**으로, node와 automation을 붙여 만든 말이다. 앞뒤 글자 n과 n 사이에 글자가 8개 있어서 n8n이라고 쓴다. 수업 자료는 2019년 베를린에서 공개된 도구라고 소개했다.

### 실행할 때마다 증거가 남는다

24회차에서 n8n을 고른 이유가 바로 이것이었다. 처음 만든 흐름은 칸이 두 개뿐이다.

```text
[Manual Trigger]  →  [HTTP Request]
 버튼을 누르면 시작     위키백과의 공개 요약 API를 읽는다
```

Execute workflow 버튼을 누르면 실행이 한 건 기록된다. 그 기록을 열면 HTTP Request 칸이 받은 응답이 그대로 남아 있어서, `title`·`description` 같은 필드를 직접 확인할 수 있다. 상태 코드까지 보려면 HTTP Request 칸의 옵션에서 응답 헤더와 상태 코드를 함께 내보내도록 켜야 한다. 이 옵션을 켜면 응답 본문은 `body` 안으로 한 겹 들어간다.

수업이 강조한 건 "결과만 보지 말고 기록을 보라"는 것이다. 화면에 "요약을 만들었다"는 결과만 남으면, 그 요약이 무엇을 읽고 만들어졌는지 알 수 없다. 실행 기록이 있으면 입력과 출력을 나란히 놓고 대조할 수 있다.

### 코딩 에이전트에게 맡길 수도 있다 — n8n CLI

n8n에는 터미널에서 쓰는 공식 {% include term.html name="CLI" %} `@n8n/cli`가 있다. 실습에서는 `npm install -g @n8n/cli`로 0.22.0을 설치했고, 명령 이름은 `n8n-cli`였다. 주소와 API 키를 한 번 저장해 두면 워크플로 목록 보기·만들기·지우기, 실행 기록 보기를 글자로 할 수 있다. 코딩 에이전트가 이 CLI를 대신 부르게 하면, 말로 시킨 흐름을 에이전트가 만들어 준다.

이때 흐름은 {% include term.html name="JSON" %} 파일 하나로 표현된다. 실습에서 받은 `wf.json`에는 이런 칸들이 있었다.

| 키 | 들어가는 것 |
| --- | --- |
| `name` | 워크플로 이름 |
| `nodes` | 칸마다 이름·종류·위치·설정(HTTP Request라면 요청할 주소) |
| `connections` | 어느 칸의 출력이 어느 칸으로 가는지 |

수업이 정한 순서는 **"만들기 전에 보여 줘 → 내가 확인하면 만들어"**였다. JSON에 적힌 주소로 실제 요청이 나가기 때문이다. 실습에서도 에이전트가 `wf.json`을 먼저 보여 주고, 확인했다고 답한 뒤에야 `workflow create`로 만들었다.

한 가지 빈칸이 있다. **CLI에는 워크플로를 새로 실행하는 명령이 없다.** 그래서 만든 흐름의 첫 실행은 n8n 화면에서 버튼을 눌러야 했고, CLI로는 끝난 실행의 기록을 조회할 수 있다고 안내받았다. 수업 자료는 실행까지 에이전트에게 맡기려면 n8n이 따로 제공하는 {% include term.html name="MCP" %} 서버를 켜야 한다고 소개했다(절차는 수업 범위 밖이었다).

### 가운데에 AI를 끼울 수도 있다

노드 5에서는 Gmail에서 오늘 받은 메일을 가져와 **AI Agent 노드**가 요약하고, 결과를 Google Sheets에 한 줄씩 적는 흐름을 Claude Code에게 맡겨 만들었다. 메일을 가져오고 시트에 적는 순서는 그래프가 정하고, 요약하는 칸 하나만 모델이 판단한다. 수업 순서에서 API 키와 Google 계정 연결은 에이전트에게 넘기지 않고 n8n 화면에서 직접 등록하게 되어 있다. JSON에는 키 값이 아니라 연결 이름만 들어간다.

정해 둔 조건으로 길을 나누고 싶을 때는 **IF 노드**를 쓴다. "제목이 비어 있지 않은가"처럼 값으로 적을 수 있는 조건이면, 같은 입력에는 언제나 같은 길로 간다. 메일을 보내거나 지우는 것처럼 바깥 상태를 바꾸는 칸은 사람이 확인한 뒤에만 지나가게 하라는 것이 수업의 권고였다({% include term.html name="HITL" %}).

### 요금은 칸 수가 아니라 실행 횟수로 센다

수업 자료는 그래프형 도구끼리도 요금을 세는 단위가 다르다고 짚었다. n8n은 워크플로 전체가 한 번 돌면 칸이 몇 개든 **execution 1회**다. Zapier는 실행된 동작 칸마다 **task 1개**로 센다. 트리거 뒤에 동작 칸이 4개 있는 흐름을 한 번 돌리면 n8n은 1회, Zapier는 4개다. 요금표 숫자만 나란히 놓고 비교하면 안 되는 이유다.

### 내 컴퓨터에 직접 띄울 수 있다

n8n은 소스 코드를 공개하는 fair-code 방식(Sustainable Use 라이선스)이다. 그래서 회사가 운영하는 n8n Cloud 말고도, 내 컴퓨터나 서버에 직접 띄울 수 있다. 이걸 셀프 호스팅이라고 한다. 수업 인스턴스는 수업 운영 측이 띄워 둔 n8n이었다. 직접 띄울 때 널리 쓰는 방법이 {% include term.html name="Docker" %}이고, 띄우는 순간 데이터 보관·백업·업데이트를 내가 책임지게 된다.

## 3. 어디서 만났나

**24회차**에서 "다음 행동은 누가 정하나"를 따지는 관찰 도구로 처음 썼다. 사람이 하나씩 시키는 방식, 정해 둔 그래프가 순서를 정하는 워크플로, 모델이 다음 행동을 고르는 에이전트를 나눌 때, 워크플로 쪽의 대표로 n8n을 띄워 놓고 실습했다.

직접 해 본 것은 세 가지다. 화면에서 Manual Trigger → HTTP Request 흐름을 만들어 실행 기록을 열어 봤고(노드 3), 같은 흐름을 Claude Code에게 n8n CLI로 만들게 했고(노드 4), Gmail 요약 흐름을 AI Agent 노드로 만들어 봤다(노드 5). 노드 4에서는 CLI 0.22.0을 설치하고 수업 인스턴스에 연결되는지 확인한 뒤, 에이전트가 보여 준 `wf.json`을 확인하고 나서 생성을 맡겼다. CLI에는 새 실행을 시작하는 명령이 없어 실행은 화면에서 했다.

다른 컴퓨터에서 같은 설치를 혼자 따라 해 보다가 헷갈린 순간도 있었다. 아래 '많이들 오해하는 지점'의 ㄱ이 그 이야기다.

## 4. 헷갈리는 개념

| 이 용어 | 비슷하지만 다른 것 | 차이 |
| --- | --- | --- |
| n8n | 워크플로 | 워크플로는 "정해 둔 순서대로 실행한다"는 **방식**이다. n8n은 그 방식을 화면에서 그리고 실행하게 해 주는 **도구** 하나다 |
| n8n | Zapier | 둘 다 "이런 일이 생기면 이렇게 한다"를 미리 정해 두는 도구다. 요금 단위가 다르고(n8n은 실행 1회, Zapier는 동작 칸마다 1개), n8n은 소스가 공개돼 내 컴퓨터에 직접 띄울 수 있다 |
| n8n | AI 에이전트 (Claude Code 등) | n8n 워크플로는 **사람이 그린 길**을 따라간다. 에이전트는 앞선 결과를 읽고 **모델이 다음 길을 고른다**. n8n 안에 AI Agent 노드를 넣어도 그 칸만 모델이 판단하고, 전체 순서는 여전히 그래프가 정한다 |
| 노드 (n8n의 칸) | 노드 (수업 자료의 단원) | n8n의 노드는 그래프 안에서 **할 일 하나를 맡은 칸**이다. 이 블로그와 수업에서 말하는 노드는 **수업 자료의 단원 하나**다. 같은 낱말이라 글에서는 처음에 "노드(그래프의 칸)"처럼 풀어 쓴다 |

## 5. 많이들 오해하는 지점

**ㄱ. "터미널이 멈추고 뭔가를 물어보면 오류가 난 것이다"**

다른 컴퓨터에서 CLI 설치를 혼자 따라 하다가 실제로 이렇게 생각했다. 화면 마지막 줄이 n8n 주소를 묻는 문장에서 멈춰 있어서 오류인 줄 알았다. 확인해 보니 위쪽 줄은 전부 정상이었다. 설치도 됐고, 저장된 접속 설정도 있었고, 워크플로 목록도 받아 왔다. 멈춘 줄은 `n8n-cli login`이 **입력을 기다리는 화면**이었을 뿐이다. 이미 설정이 있었으니 `Ctrl + C`로 빠져나오면 됐다. 오류는 보통 "error", "실패", "인식되지 않습니다" 같은 말로 나온다. 물음표나 괄호 속 기본값이 보이면 프로그램이 내 답을 기다리는 중이다. 또 목록이 JSON이 아니라 표로 나온 것도 정상이었다. 이 CLI는 사람이 터미널에서 직접 실행하면 표로, 다른 프로그램이 결과를 받아 가면 JSON으로 내보낸다.

**ㄴ. "가운데에 AI 노드를 넣으면 워크플로가 에이전트가 된다"**

노드 5의 Gmail 요약 흐름에는 AI Agent 노드가 들어 있지만, 메일을 가져오고 → 요약하고 → 시트에 적는 순서는 처음부터 끝까지 그래프가 정한다. 모델이 판단하는 건 "이 메일을 어떻게 요약할까" 하나다. 그래서 문제가 생기면 확인할 곳도 나뉜다. 순서가 이상하면 그래프를, 요약이 이상하면 AI Agent 칸의 입력과 출력을 본다. 요약은 모델이 쓴 문장이라 원래 메일과 다를 수 있으니, 실행 기록에서 둘을 나란히 놓고 대조해야 한다.

**ㄷ. "칸을 많이 넣을수록 요금이 많이 나온다"**

n8n은 칸 수가 아니라 **흐름 전체가 몇 번 실행됐는지**로 센다. 칸을 4개 두든 10개 두든 한 번 돌면 1회다. 반대로 칸이 적어도 정해진 시각마다 자동으로 돌게 켜 두면, 실행 횟수와 기록이 계속 쌓인다. 또 AI Agent 노드를 쓰면 n8n 요금과 별개로 모델 호출 비용과 한도가 따라온다. 노드 5 실습 자료도 오늘 받은 메일이 많으면 모델 호출이 메일 수만큼 늘어 무료 등급 한도에 걸릴 수 있다고 적었다.
