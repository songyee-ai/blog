## 한 줄 정의

> 챗봇의 답을 질문·근거와 함께 LLM에게 한 번 더 보여 주고, 정해 둔 기준표대로 채점하게 하는 방법

---

## 1. 비유로 이해하기

받아쓰기 시험이 끝나면 선생님이 짝꿍과 시험지를 바꾸게 한다. 그리고 칠판에 **정답**과 **채점 기준**을 적어 준다. "정답과 같은 낱말이면 동그라미, 정답에 없는 낱말을 써 넣었으면 세모, 모르는 문제를 '모름'이라고 솔직히 적었으면 깎지 않는다, 맨 아래에 점수와 한 줄 평을 쓴다." 짝꿍은 이 기준만 보고 채점한다. 선생님 혼자 서른 장을 다 보는 것보다 훨씬 빠르다.

그런데 어떤 날은 짝꿍이 없어서 **자기 시험지를 자기가 채점**해야 한다. 그러면 자기가 틀리게 쓴 낱말을 맞게 썼다고 믿어 버리기 쉽다. 다른 눈으로 한 번 더 보는 효과가 없어지기 때문이다.

{% include figure.html src="/assets/images/term-llm-as-a-judge/judge-flow.svg" alt="위에 질문, 근거자료, 답변 세 상자가 있다. 근거자료는 받아쓰기의 정답지, 답변은 채점할 시험지에 해당한다. 세 상자가 가운데 평가자 LLM 상자로 모이고, 평가자는 채점 기준표와 JSON만 출력하라는 지시를 받으며 스트리밍과 생각 출력을 끄고 온도 0으로 돈다. 평가자는 grounded, noHalluc, cited, refusal, score, comment 여섯 칸짜리 JSON을 돌려준다. 맨 아래 빨간 상자에는 답한 모델과 채점한 모델이 같으면, 23회차처럼 둘 다 qwen3.5:2b이면, 독립 심사가 아니라 거친 신호로 읽어야 한다고 적었다" caption="그림 1. 평가자에게 세 가지를 넣고 여섯 칸을 돌려받는다" %}

그래서 실제로는, 챗봇이 쓴 답을 사람이 하나하나 읽는 대신 **또 한 번 {% include term.html name="LLM" %}을 불러** 질문·근거자료·답변을 함께 보여 주고, 미리 정한 기준대로 채점표를 써 달라고 하는 것이 LLM-as-a-Judge다. 칠판의 정답이 근거자료, 채점 기준이 평가 {% include term.html name="프롬프트" %}, 짝꿍이 평가자 모델이다. 자기 시험지를 자기가 채점하는 날은, 답을 쓴 모델이 자기 답을 다시 채점하는 **자기평가**에 해당한다.

## 2. 왜 필요한가

### 정답이 한 줄이 아닌 답을 재려고

"3 + 4는?"처럼 정답이 하나면 프로그램이 답과 정답을 글자째 맞춰 보면 된다. 그런데 챗봇 답은 문장이다. 같은 뜻을 열 가지 말로 쓸 수 있고, 맞는 말 사이에 틀린 말 한 줄이 끼기도 한다. 글자를 맞춰 보는 방식으로는 "근거에 있는 말인가", "없는 말을 지어냈나"를 가르기 어렵다. 문장을 읽고 판단하는 일은 LLM이 할 수 있으니, 그 일을 평가에 쓰는 것이다.

사람이 다 읽는 방법도 있지만, 질문을 고치거나 {% include term.html name="프롬프트" %} 한 줄을 바꿀 때마다 수십 개를 다시 읽기는 힘들다. 평가자 모델은 사람 대신 답마다 채점표를 내 준다. 작업물에서 한 번 돌린 출력을 보면 판정에 9.0초가 걸렸다.

### 기준을 칸으로 못 박는다

"이 답 괜찮아?"라고 물으면 평가자도 "좋은 답입니다" 같은 인상만 돌려준다. 그래서 23회차 노드는 평가자에게 **여섯 칸짜리 {% include term.html name="JSON" %}만** 내라고 시켰다.

| 칸 | 묻는 것 | 값 |
| --- | --- | --- |
| `grounded` | 답의 내용이 근거자료에서 나왔나 | true / false |
| `noHalluc` | 근거에 없는 사실을 지어내지 않았나 | true / false |
| `cited` | 답 안에 근거 조각의 `[ID]` 표시가 있나 | true / false |
| `refusal` | 근거에 답이 없어서 "없다"고 말했나 | true / false |
| `score` | 위 세 기준(grounded·noHalluc·cited)을 반영한 점수 | 0~100 정수 |
| `comment` | 왜 그렇게 봤는지 | 한국어 한두 문장 |

칸이 정해져 있으면 화면을 만드는 쪽은 평가자의 말을 짐작해서 읽을 필요가 없다. `cited`가 false면 "출처 없음" 배지를 붙이고, `refusal`이 true면 "정당한 거절" 배지를 붙이면 된다. 질문을 여러 개 돌려 `grounded:true`가 몇 개인지 세면 숫자 하나로 비교할 수도 있다.

### 채점은 흔들리지 않게 부른다

평가자를 부를 때는 답을 만들 때와 설정이 다르다.

```text
stream:false, think:false, format:"json", options:{temperature:0}
```

채점표는 조각조각 보여 줄 필요가 없으니 스트리밍을 끄고, 생각 과정 출력도 끈다. `format:"json"`은 JSON 모양으로만 답하게 하고, {% include term.html name="temperature" %} 0은 같은 입력이면 같은 채점이 나오게 한다. 그래도 모델은 가끔 틀을 벗어난다. 노드는 100점 만점인데 5점 만점처럼 점수를 내면 100점으로 환산하고, JSON을 못 읽으면 `judgeError` 배지만 남긴 채 이미 나온 답은 그대로 두라고 했다. 평가자가 실패했다고 답까지 지우면 안 되기 때문이다.

### "없다"고 한 답을 실패로 세지 않으려고

`refusal` 칸이 따로 있는 이유가 있다. 자료에 없는 날씨를 물었는데 챗봇이 "자료에 없다"고 답했다면, 그건 **경계를 지킨 좋은 답**이다. 이 칸이 없으면 "답을 못 했다"로 섞여 점수가 깎인다. 무엇이든 답하는 챗봇이 아니라 자료 안에서만 답하는 챗봇을 만들려면, 정직한 거절을 따로 세어야 한다.

## 3. 어디서 만났나

**23회차** 노드 7에서 RAG 챗봇의 마지막 단계로 나왔다. 답변을 만든 뒤 평가자를 한 번 더 두고, 위의 여섯 칸을 배지로 보여 주는 구성이었다. 노드는 답변 모델과 평가 모델이 같은 2B 모델(qwen3.5:2b)이라 **독립 심사가 아니고, 교육용의 거친 신호**라고 처음부터 못 박았다.

## 4. 헷갈리는 개념

| 이 용어 | 비슷하지만 다른 것 | 차이 |
| --- | --- | --- |
| LLM-as-a-Judge | 사람의 좋아요·싫어요 | 평가자 LLM은 **기준표대로** 칸을 채운다. 좋아요·싫어요는 사람이 **써 보니 어땠는지**를 남긴다. 둘이 어긋나면 기준이 놓친 것이 있거나 사람이 근거를 놓친 것이니 다시 읽어 볼 거리다 |
| LLM-as-a-Judge | {% include term.html name="F1" %} 같은 계산 점수 | F1은 정답 목록과 **맞춰 보는 계산**이라 같은 입력이면 늘 같은 값이다. 평가자 LLM은 문장을 **읽고 판단**하므로 뜻을 볼 수 있지만, 판단이 틀릴 수도 있다 |
| LLM-as-a-Judge | {% include term.html name="셀프 컨시스턴시" %} | 셀프 컨시스턴시는 같은 질문에 여러 번 답하게 해 다수결로 **답을 고르는** 방법이다. LLM-as-a-Judge는 이미 나온 답을 **채점하는** 쪽이다 |
| 자기평가 | 독립 평가 | 자기평가는 답한 모델이 자기 답을 채점한다. 독립 평가는 다른 모델(노드가 예로 든 Gemini 같은)이나 사람이 채점한다. 23회차 로컬 판정은 자기평가였다 |

## 5. 많이들 오해하는 지점

**ㄱ. "평가자가 통과를 줬으니 그 답은 맞다"**

평가자도 LLM이라 틀린다. 작업물에서 `[DC-010]`을 적은 답을 `cited ✗`로 채점한 것처럼, 눈에 보이는 표시조차 놓칠 수 있다. 판정은 **어디를 다시 읽을지 알려 주는 신호**이지 결론이 아니다. 배지만 보지 말고 답변 본문, 검색 근거, 평어를 함께 읽는다. `[ID]`가 있는지처럼 프로그램이 직접 셀 수 있는 것은 평가자에게 맡기지 않고 코드로 세는 편이 정확하다.

**ㄴ. "자기가 쓴 답이니 자기가 제일 잘 채점한다"**

그렇지 않다. 같은 모델이 쓰고 채점하면 독립된 심사가 아니어서, 작은 사실 차이나 빠진 맥락을 거칠게 넘길 수 있다. 23회차 작업물에서는 반대로 있는 `[ID]`를 없다고 채점하기도 했다. 어느 쪽이든 점수 하나를 그대로 믿기 어렵다는 뜻이다. 다른 모델에게 같은 답을 채점시켜 나란히 보거나, 평가자의 판정을 사람이 다시 채점해 보는 것이 다음 걸음이다.

**ㄷ. "`refusal:true`면 챗봇이 실패한 것이다"**

근거에 답이 없는데 없다고 말했다면 그건 **정당한 거절**이다. 지어내서 답하는 것보다 낫다. 이 칸을 실패로 세면, 점수를 올리려다 챗봇이 지어내서라도 답하게 만드는 쪽으로 고칠 위험이 있다.
