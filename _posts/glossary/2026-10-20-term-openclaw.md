## 한 줄 정의

> 내 컴퓨터에 계속 켜 두고 WebChat·Telegram 같은 채팅으로 일을 맡기면, 정해 둔 권한 안에서 파일과 도구를 다뤄 주는 오픈소스 개인 비서 에이전트

## 1. 비유로 이해하기

집에 **집사 로봇**이 한 대 산다고 해 보자. 이 로봇은 잠들지 않는다. 거실에서 말로 부탁해도, 밖에서 휴대폰 문자로 부탁해도, 냉장고에 쪽지를 붙여도 같은 로봇이 받는다. 어디로 부탁했든 로봇은 같은 수첩에 적어 두기 때문에, 아까 거실에서 한 이야기를 문자로 이어 가도 알아듣는다.

대신 이 로봇은 **주인이 건넨 열쇠로 열리는 방**에만 들어갈 수 있다. 서재 열쇠만 줬다면 안방 서랍은 못 연다. 그리고 "매일 새벽 3시에 수첩 정리" 같은 일은 아무도 시키지 않아도 시간이 되면 스스로 한다.

{% include figure.html src="/assets/images/term-openclaw/openclaw-layers.svg" alt="맨 위에 창구 세 개(터미널 채팅 화면, WebChat, Telegram 봇)가 있고, 셋 다 화살표로 가운데의 Gateway로 모인다. Gateway는 127.0.0.1:18789에서 기다리며 메시지를 어느 세션·에이전트로 보낼지 정하고, 데몬으로 등록돼 터미널 창과 상관없이 돈다. 그 아래 에이전트 런타임이 Claude 모델을 부르고 명령 실행·파일 읽기 같은 도구를 쓴다. 맨 아래 ~/.openclaw 폴더에 설정 파일과 에이전트별 SQLite 대화 기록이 쌓인다" caption="그림 1. 창구는 여러 개, 접수처는 하나, 기록도 한곳" %}

그래서 실제로는, 집사 로봇이 **OpenClaw**이고 거실·문자·쪽지 같은 부탁 통로가 **채널**(WebChat, Telegram 등)이다. 잠들지 않고 부탁을 받는 부분이 {% include term.html name="게이트웨이" %}(Gateway), 그 수첩이 `~/.openclaw` 아래의 대화 기록, 건네준 열쇠가 권한 설정, 새벽 3시 정리 같은 일이 예약 작업({% include term.html name="cron" %})이다.

## 2. 왜 필요한가

### 계속 켜 있어야 하는 일이 있다

Claude Code 같은 코딩 에이전트는 보통 내가 터미널을 열고 말을 걸 때만 움직인다. 창을 닫으면 대화도 끝난다. 그런데 "휴대폰으로 보낸 메시지에 답해 줘", "30분마다 상태를 살펴 줘" 같은 일은 내가 화면 앞에 없을 때 일어난다. 그러려면 누군가 **계속 깨어 있어야** 한다.

OpenClaw는 그 깨어 있는 부분을 {% include term.html name="데몬" %}으로 띄운다. 11월 4일에 예약 목록을 보니 내가 만들지 않은 기본 작업 두 개가 들어 있었다.

```text
Memory Dreaming   매일 03시     기억 정리 (cron 표기 0 3 * * *)
Heartbeat         30분마다
```

내가 아무것도 시키지 않았는데 이미 시간표가 있다는 것, 그게 "계속 켜 두는 도구"라는 뜻이다.

### 어느 창구로 말해도 같은 대화로 이어진다

실습에서 온보딩을 마치자 터미널 안 채팅 화면(TUI)이 열렸고, 거기서 한 대화가 나중에 브라우저로 연 WebChat의 Main Session에도 그대로 떠 있었다. 화면은 달라도 **같은 main 세션**(표준 키 `agent:<agentId>:main`)으로 이어진 것이다. 기록도 한곳에 쌓였다. 메시지를 보내기 전후로 파일 목록을 비교해 보니, 바뀐 곳은 `~/.openclaw/agents/main/agent/` 아래의 SQLite 파일 3개뿐이었다.

창구마다 따로 노는 챗봇을 여러 개 두면 "아까 그 이야기"가 끊긴다. OpenClaw는 창구를 여럿 열어 두되 받는 곳을 하나로 모아 이 문제를 푼다.

### 이름이 세 번 바뀌어서, 찾을 때 옛 이름도 알아야 한다

```text
Warelay  →  Clawdbot  →  Moltbot (2026-01-27)  →  OpenClaw (2026-01-30)
```

시작은 WhatsApp 메시지를 잇는 프로그램이었고, 바닷가재 마스코트가 붙으며 Clawdbot이 됐다. 상표 문제로 이름을 바꿔야 해서 커뮤니티가 "탈피"라는 뜻의 Moltbot을 골랐고, 사흘 뒤 지금 이름으로 정해졌다. 껍데기(이름)를 갈아입어도 속의 바닷가재(코드와 사람들)는 그대로라는 셈이다.

오래된 글이나 오류 해결법을 찾을 때는 Clawdbot, Moltbot으로도 검색해야 한다. Linux·WSL에서는 예전 서비스 이름 `clawdbot-gateway`가 남아 있으면 지금 이름으로 옮겨 준다고 수업 자료에 나온다.

### 작은 코어 위에 조립한 도구다

노드 6에서 본 **pi**는 터미널에서 쓰는 작은 코딩 에이전트다. 초기 OpenClaw는 이 pi를 엔진으로 품고, 그 위에 메시지를 받는 Gateway를 얹은 모양이었다. 지금은 자체 런타임으로 바뀌었지만, "생각하고 도구를 쓰는 코어" 위에 "창구·권한·예약"을 덧붙인 구조는 그대로다. OpenClaw를 뜯어 보면 에이전트 도구가 어떤 층으로 이루어지는지가 보인다.

### 켜 둔 만큼 지켜야 할 것도 늘어난다

계속 켜 있고, 바깥 메시지를 받고, 내 파일을 다룬다. 편한 만큼 조심할 곳도 많다. 실습에서 `openclaw doctor --lint`는 경고 두 개를 냈다.

- `gateway.bind` — Gateway가 이 컴퓨터 안(loopback)에만 열려 있다는 안내. 다른 기기를 붙일 계획이 없어 그대로 뒀다.
- `gateway.auth.token` — 설정 파일에 토큰이 평문으로 적혀 있다는 지적. 보관함으로 옮기는 명령(`openclaw secrets configure`)이 함께 안내됐다.

누가 봇에게 말을 걸 수 있는지는 {% include term.html name="페어링" %}으로, 바깥 글에 숨은 지시는 {% include term.html name="프롬프트 인젝션" %} 대비로 따로 막는다.

## 3. 어디서 만났나

**27회차**의 주인공이었다. WSL2 Ubuntu에 Node 24를 맞추고 `npm install -g openclaw@latest --allow-scripts=openclaw`로 2026.10.5를 설치한 뒤 온보딩으로 첫 설정을 했다. 온보딩이 끝나자 Gateway가 systemd 사용자 서비스(`openclaw-gateway.service`)로 켜져 있었다. 모델 연결은 API 키 대신 **claude-cli** 경로(로그인해 둔 Claude 구독을 다시 쓰는 방식)를 골랐다.

그다음 `openclaw doctor`, `openclaw gateway status`로 상태를 확인하고, WebChat에 첫 메시지를 보내고, 보내기 전후의 파일 목록을 비교했다(노드 2·3). Telegram 연결, 모니터링, 예약 작업 실습(노드 4·8·9)도 진행했지만 결과는 따로 적어 두지 않았다. 11월 4일에 확인했을 때 설정 파일에는 Telegram 채널이 등록돼 있었고, 예약 목록에는 기본 작업 두 개만 있었다.

## 4. 헷갈리는 개념

| 이 용어 | 비슷하지만 다른 것 | 차이 |
| --- | --- | --- |
| OpenClaw | Claude Code | 둘 다 모델에게 도구를 쥐여 주는 에이전트다. Claude Code는 **내가 터미널을 열 때** 일하는 코딩 도우미, OpenClaw는 **계속 켜 두고 여러 채팅 창구로** 일을 받는 비서에 가깝다 |
| OpenClaw | Claude (모델) | OpenClaw는 모델을 **부르는 쪽**이다. 실습에서는 Claude Opus 5.5를 불렀지만, 연결 방식을 바꾸면 다른 모델도 쓸 수 있다. 똑똑함은 모델에서, 창구·권한·기록은 OpenClaw에서 나온다 |
| OpenClaw | 게이트웨이 (Gateway) | Gateway는 OpenClaw 안의 **한 부분**, 늘 켜져서 메시지를 받아 나눠 주는 접수처다. OpenClaw는 Gateway·런타임·채널·설정을 다 합친 이름이다 |
| OpenClaw | pi | pi는 터미널에서 쓰는 **작은 에이전트 코어**다. 채널 연결이나 예약 기능은 기본으로 들어 있지 않다. OpenClaw는 그런 코어 위에 창구와 예약을 얹은 완성품 쪽이다 |

## 5. 많이들 오해하는 지점

**ㄱ. "채팅 화면에 명령어를 치면 그 명령이 실행된다"**

실습 기록에 실제로 있던 장면이다. 온보딩이 끝나고 채팅 화면(TUI)에 있는 줄 모르고 `openclaw doctor`를 입력했다. 이건 터미널 명령이 아니라 **에이전트에게 보낸 메시지**가 됐다. 에이전트는 그 글을 "진단해 달라"는 부탁으로 읽고, 스스로 판단해 `openclaw doctor --lint`를 도구로 실행한 뒤 결과를 풀어 답했다. 답 끝에는 "토큰을 보관함으로 옮길까요?"라는 설정 변경 제안까지 붙었다(답하지 않았다).

내가 친 명령과 에이전트가 고른 명령은 다를 수 있다. 이번엔 읽기만 하는 `--lint`였지만, 채팅창에 쓴 글은 언제나 "부탁"이고, 무엇을 실행할지는 모델이 정한다는 점을 기억해야 한다.

**ㄴ. "에이전트가 정리해 준 결과는 원래 출력과 같다"**

같은 doctor 결과를 bash에서 직접 친 출력과 나란히 놓아 봤다. 검사 36개, 경고 2개, 오류 없음, 경고 이름은 같았다. 그런데 답변에만 "30개 항목은 해당 없거나 선택 항목이라 건너뜀"이라는 문장이 있었다. 원래 출력에는 그 숫자가 없어서 맞는지 확인할 수 없었다. 영어 문장 한 줄이 섞이기도 했다. 답변은 모델이 쓴 문장이고, 실제로 일어난 일은 도구 실행 결과에 남는다. 둘은 다를 수 있다.

**ㄷ. "연습 폴더에서 설치하면 그 폴더 안에만 흔적이 남는다"**

명령은 연습 폴더에서 쳤지만, 설정·대화 기록·작업 폴더는 전부 홈 아래 `~/.openclaw`에 생겼다. `openclaw.json`과 백업 4개, 에이전트별 SQLite 파일, `workspace/`가 거기 있었다. 폴더 이름만으로는 격리되지 않는다. 그래서 수업용 계정과 수업용 키만 쓰고, 다 끝나면 `~/.openclaw`까지 지워야 깨끗해진다.
