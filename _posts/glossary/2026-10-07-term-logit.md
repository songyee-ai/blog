## 한 줄 정의

> 모델이 후보마다 매긴 날것의 점수. 소프트맥스를 거쳐야 비로소 확률이 된다

---

## 1. 비유로 이해하기

반 친구들이 다음 주 급식 메뉴 게시판에 스티커를 붙였다. 좋으면 웃는 얼굴(+1), 싫으면 찡그린 얼굴(-1)이다. 다 붙이고 나서 메뉴마다 더하니 이렇게 나왔다.

```
떡볶이  +2
카레    +1
나물    -1
```

이 숫자는 "떡볶이가 나올 확률"이 아니다. 음수도 있고, 셋을 더해도 2일 뿐 100이 되지 않는다. 그냥 **친구들 마음이 어느 쪽으로 얼마나 기울었는지** 적어 둔 점수다. 영양사 선생님이 이 점수를 보고 "그럼 떡볶이가 나올 가능성을 몇 %로 잡자"고 바꾸는 건 그다음 일이다.

실제로는, 언어 모델이 다음 {% include term.html name="토큰" %}을 고를 때 후보 하나하나에 이런 점수를 매긴다. 이 점수가 로짓이고, 이것을 "다 더하면 1인 확률"로 바꾸는 계산이 {% include term.html name="소프트맥스" %}다.

{% include figure.html src="/assets/images/term-logit/only-gaps-matter.svg" alt="떡볶이 2, 카레 1, 나물 -1이라는 로짓을 소프트맥스로 바꾸면 70.5%, 26.0%, 3.5%가 된다. 세 점수에 모두 10을 더해도 확률은 그대로지만, 0.5로 나누면 87.9%, 11.9%, 0.2%로 1등이 세지고 2로 나누면 54.7%, 33.1%, 12.2%로 고르게 퍼진다. 세 경우 모두 순서는 바뀌지 않는다" caption="그림 1. 같은 로짓을 더하고 나눠 보기. 확률을 바꾸는 것은 점수 사이의 간격이다" %}

## 2. 왜 필요한가

### 점수와 확률을 나눠 두면 손대기 쉽다

모델의 마지막 층은 숫자를 곱하고 더하는 계산이라, 결과는 -7이든 13이든 아무 실수나 나온다. 이걸 곧장 확률이라고 부를 수는 없으니, 맨 끝에 소프트맥스를 한 번 거쳐 확률표로 바꾼다.

그런데 점수 단계가 따로 있으면 **확률로 바꾸기 직전에 손을 댈 수 있다.** 생성 설정의 손잡이들이 바로 여기를 만진다.

- {% include term.html name="temperature" %} — 로짓 전체를 이 숫자로 나눈 뒤 소프트맥스에 넣는다. 1보다 작으면 간격이 벌어지고, 크면 좁아진다(그림 1의 ②·③).
- {% include term.html name="top_k/top_p" %} — 점수가 높은 후보 몇 개만 남기고 나머지는 뽑기에서 빼 버린다.

### 숫자 자체보다 간격이 중요하다

그림 1의 ①처럼 모든 로짓에 똑같이 10을 더해도 확률은 소수점까지 그대로다. 소프트맥스는 "누가 누구보다 얼마나 앞서는가"만 보기 때문이다.

간격이 확률에 주는 영향은 이렇게 셀 수 있다. 두 후보의 로짓 차이가 1이면 앞선 쪽의 확률이 약 2.7배(e¹), 차이가 3이면 약 20배(e³)다. 그림 1에서 떡볶이(2)와 나물(-1)은 차이가 3이라, 70.5%와 3.5%가 정말로 약 20배 차이 난다.

```python
import numpy as np

logits = np.array([2.0, 1.0, -1.0])         # 떡볶이, 카레, 나물

def softmax(x):
    e = np.exp(x)
    return e / e.sum()

softmax(logits)          # → [0.705, 0.260, 0.035]
softmax(logits + 10)     # → [0.705, 0.260, 0.035]  더해도 그대로
softmax(logits / 0.5)    # → [0.879, 0.119, 0.002]  온도 0.5
```

### 다른 자리에서 만나는 로짓 — 확률 하나를 펴 놓은 값

로짓이라는 말은 원래 통계에서 먼저 쓰였다. 확률 p 하나를 아래 식으로 바꾼 값을 로짓이라고 부른다.

```
logit(p) = ln( p / (1 - p) )

p = 0.5  →  0
p = 0.9  →  2.1972
p = 0.1  → -2.1972
p = 0.99 →  4.5951
```

0~1 사이에 갇힌 확률을 -∞~+∞까지 쭉 펴 놓은 것이다. 거꾸로 되돌리는 함수가 시그모이드(sigmoid)라, 학습 중에는 아무 숫자나 마음대로 바꿔 가며 고치고, 쓸 때만 시그모이드로 0~1 확률로 되돌리는 방식에 자주 쓰인다.

두 뜻은 뿌리가 같다. "확률로 바꾸기 전의 자유로운 점수"라는 점에서 한 가족이다. 실제로 후보가 둘뿐이면, 두 로짓에 소프트맥스를 쓴 결과는 두 로짓의 **차이**를 시그모이드에 넣은 결과와 같다.

## 3. 어디서 만났나

**20회차**에서 생성 설정(temperature, top_k)을 바꿔 같은 질문을 여러 번 보낸 강의 실험 뒤에, "그 손잡이를 돌릴 때 안에서 무슨 일이 일어나는가"를 설명하는 자리에서 정식으로 나왔다. 모델은 후보마다 로짓을 내고, 소프트맥스가 그걸 확률로 바꾸고, 그 확률에서 하나를 뽑는다는 두 단계 구조였다. "9.11과 9.9 중 어느 쪽이 더 큰가요?"를 temperature 0으로 세 번 보내면 세 번 다 같은 오답이 나왔는데, 이건 강의 기록에도 있고 내가 스텝 2에서 직접 돌린 결과(세 답이 바이트까지 동일)도 같았다. 온도는 로짓의 **순서**를 바꾸지 않으니, 틀린 답이 1등이면 그 1등이 더 확실하게 뽑힐 뿐이다.

이름은 그 전에도 두 번 스쳤다. 소프트맥스 용어 글에 "소프트맥스에 들어가는 원점수"로 이미 나왔고, 16회차 3D 스플랫 작업에서는 불투명도 0.9를 파일에 로짓 값 2.1972로 바꿔 넣었다. 위 2의 마지막 소제목이 그 두 번째 뜻이다.

## 4. 헷갈리는 개념

| 이 용어 | 비슷하지만 다른 것 | 차이 |
| --- | --- | --- |
| 로짓 | 확률 | 로짓은 음수도 되고 합이 정해져 있지 않은 **점수**. 확률은 0~1 사이이고 후보 전체를 더하면 1 |
| 로짓 | 소프트맥스 | 로짓은 **재료**, 소프트맥스는 그 재료를 확률로 바꾸는 **계산** |
| 로짓 | 로그 확률 (logprob) | API가 돌려주는 logprob은 소프트맥스를 **지난 뒤** 확률에 로그를 씌운 값이라 늘 0 이하다. 로짓은 소프트맥스 **앞**의 값 |
| 로짓 | temperature | temperature는 로짓을 나누는 **숫자 하나**. 로짓 자체를 새로 만들지는 않는다 |

## 5. 많이들 오해하는 지점

**ㄱ. "로짓이 가장 높은 후보가 정답이다"**

로짓이 높다는 건 **모델이 그쪽으로 가장 기울었다**는 뜻일 뿐이다. 모델이 질문을 잘못 읽었다면 틀린 답이 1등 점수를 받는다. 이때 온도를 낮추면 그 틀린 1등이 더 자주 뽑힐 뿐 고쳐지지 않는다. 답을 바로잡으려면 점수를 만지는 손잡이가 아니라 질문이나 지시 쪽을 고쳐야 한다.

**ㄴ. "로짓 4는 로짓 2보다 두 배 그럴듯하다"**

로짓은 나눗셈으로 비교하는 숫자가 아니다. 중요한 건 **차이**다. 4와 2는 차이가 2이므로 확률로는 약 7.4배(e²) 차이가 난다. 반대로 102와 100도 차이가 2라서 똑같이 약 7.4배다. 숫자가 크다고 더 확실한 게 아니라 간격이 클수록 확실한 것이다.

**ㄷ. "API에서 보이는 logprobs가 로짓이다"**

일부 API가 토큰별로 돌려주는 `logprobs`는 이름이 비슷해서 헷갈리지만, 소프트맥스를 이미 지난 **확률에 로그를 씌운 값**이다. 그래서 -0.1, -2.3처럼 늘 0 이하로 나온다(0이면 확률 100%). 로짓은 보통 모델 안에 있어서, 직접 보려면 대개 모델을 내 손으로 돌리면서 꺼내 봐야 한다.
