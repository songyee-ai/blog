## 한 줄 정의

> 프로그램과 그 프로그램이 돌아가는 데 필요한 것을 한 통(컨테이너)에 담아, 어느 컴퓨터에서든 같은 모습으로 띄우게 해 주는 도구

---

## 1. 비유로 이해하기

소풍날 **도시락통**을 떠올려 보자. 통 하나에 밥, 반찬, 숟가락, 젓가락, 물티슈까지 다 들어 있다. 그래서 공원 벤치에서 열든, 버스 안에서 열든, 친구네 집에서 열든 똑같은 점심을 먹을 수 있다. "거기에 숟가락 있어?"라고 미리 물어볼 필요가 없다.

급식실에는 **견본 도시락**이 하나 있다. 이 견본을 보고 똑같은 도시락을 몇 개든 싼다. 견본 자체는 건드리지 않는다. 아이들이 받아 가는 건 견본을 따라 싼 도시락 한 통 한 통이다.

다 먹은 도시락통은 씻어서 비운다. 그런데 소풍 중에 받은 **가정통신문**을 도시락통에 넣어 두었다면? 통을 씻을 때 같이 버려진다. 그래서 집에 가져가야 할 종이는 도시락통이 아니라 **가방 앞주머니**에 넣는다.

{% include figure.html src="/assets/images/term-docker/image-container-volume.svg" alt="왼쪽 위에 이미지 n8nio/n8n을 '앱과 필요한 환경을 통째로 싸 둔 견본, 바뀌지 않는다'로 그리고, docker run 화살표로 오른쪽 '내 컴퓨터' 점선 상자 안의 컨테이너로 이었다. 컨테이너는 이미지로 띄운 실행 중인 한 통으로, 안에서 n8n이 돌며 5678번 문으로 화면을 열고, --rm 때문에 멈추면 지워지며 안에 둔 임시 파일도 사라진다. 컨테이너 아래에는 -v n8n_data:/home/node/.n8n 양방향 화살표로 볼륨 n8n_data를 이었다. 볼륨은 컨테이너 바깥 서랍으로, 워크플로와 설정이 남아 새로 띄워도 이어서 쓴다. 왼쪽 아래 브라우저(127.0.0.1:5678)에서 -p 5678:5678 화살표가 컨테이너로 들어간다. 맨 아래에 -p 앞 숫자는 내 컴퓨터 쪽 문, 뒤 숫자는 컨테이너 안쪽 문이라는 설명과 수업 자료에 실린 공식 명령 두 줄을 적었다" caption="그림 1. 견본(이미지)으로 한 통(컨테이너)을 띄우고, 남길 것은 바깥 서랍(볼륨)에 둔다" %}

그래서 실제로는, 도시락 한 통이 **컨테이너**, 견본 도시락이 **이미지**, 가방 앞주머니가 **볼륨**이다. Docker는 이미지로 컨테이너를 띄우고, 멈추고, 지우는 일을 해 주는 도구다. 컨테이너 안에는 프로그램과 그 프로그램이 기대하는 파일·라이브러리·설정이 함께 들어 있어서, 내 노트북에서든 서버에서든 비슷한 조건으로 돌아간다.

## 2. 왜 필요한가

### "내 컴퓨터에서는 되는데"를 줄이려고

프로그램 하나를 돌리려면 그 프로그램만 있으면 되는 게 아니다. 특정 버전의 Node.js나 파이썬, 몇 가지 라이브러리, 정해진 폴더 구조가 함께 맞아야 한다. 컴퓨터마다 이 조합이 조금씩 달라서, 내 컴퓨터에서 되던 게 친구 컴퓨터나 서버에서는 안 되는 일이 흔하다.

Docker는 이 조합을 통째로 이미지 하나에 담는다. 받는 쪽은 Docker만 설치돼 있으면 된다. Windows와 macOS에서는 Docker Desktop을 켜 두어야 하고, Windows의 Docker Desktop은 보통 {% include term.html name="WSL" %} 2 위에 리눅스 환경을 띄워 그 안에서 컨테이너를 돌린다. 운영체제마다 필요한 프로그램을 따로 맞추는 수고가 줄어든다. 수업 자료는 그래서 n8n을 직접 띄울 때(셀프 호스팅) 널리 쓰이는 출발점이 Docker라고 소개했다.

### 한 줄 명령을 뜯어 보기

24회차 노드 7에 실린 n8n 공식 문서의 실행 예는 두 줄이다.

```bash
docker volume create n8n_data
docker run -it --rm --name n8n -p 5678:5678 -v n8n_data:/home/node/.n8n n8nio/n8n
```

첫 줄은 `n8n_data`라는 이름의 볼륨(바깥 서랍)을 만든다. 둘째 줄을 조각내 보면 이렇다.

| 조각 | 뜻 |
| --- | --- |
| `docker run` | 이미지로 컨테이너를 하나 띄운다 |
| `n8nio/n8n` | 맨 끝에 오는 이것이 쓸 이미지 이름이다 |
| `--name n8n` | 띄운 컨테이너에 `n8n`이라는 이름을 붙인다 |
| `-p 5678:5678` | 내 컴퓨터의 5678번 문을 컨테이너 안의 5678번 문(n8n 화면)에 잇는다 |
| `-v n8n_data:/home/node/.n8n` | 컨테이너 안에서 n8n이 데이터를 쓰는 폴더를 바깥의 `n8n_data` 볼륨에 잇는다 |
| `--rm` | 컨테이너가 멈추면 컨테이너를 지운다. 볼륨에 쓴 데이터는 남는다 |
| `-it` | 터미널에서 컨테이너의 출력을 보고 입력도 넣을 수 있게 연다 |

이렇게 띄운 뒤 브라우저에서 `http://127.0.0.1:5678`을 열면 n8n 화면이 보이는 구조다. `127.0.0.1`은 "지금 이 컴퓨터"를 가리키는 주소다. 다만 브라우저에 이 주소를 친다고 문이 나에게만 열리는 건 아니다. `-p 5678:5678`은 보통 이 컴퓨터의 모든 네트워크 쪽으로 문을 열어서, 방화벽이 막지 않으면 같은 와이파이의 다른 기기도 들어올 수 있다. 나만 쓰려면 `-p 127.0.0.1:5678:5678`처럼 앞에 주소를 붙인다. 수업 자료는 이 두 줄이 살펴보기용 최소 구성이고, 공식 문서는 여러 설정을 파일 하나에 적어 두는 Docker Compose 방식을 권한다고 덧붙였다.

### 컨테이너와 볼륨을 나누는 이유

컨테이너는 쓰고 버리기 쉽게 만든 통이다. 새 버전 이미지가 나오면 컨테이너를 지우고 새 이미지로 다시 띄우면 된다. 그런데 n8n의 워크플로와 실행 기록까지 컨테이너 안에만 있었다면, 지우는 순간 같이 사라진다. 그래서 오래 남길 데이터는 볼륨에 둔다. 수업 자료의 셀프 호스팅 표도 볼륨을 "이미지를 바꾸거나 컨테이너를 다시 띄운 뒤에도 워크플로와 설정을 이어서 쓸 때" 필요한 것으로 정리했다.

볼륨이 실제로 디스크 어디에 저장되는지, 어떻게 백업하는지는 Docker 설정과 운영체제마다 다르다. 수업 자료도 이 부분은 직접 확인하라고 적었다.

### 규모가 커지면 붙는 것들

수업 자료는 상황에 따라 구성을 고르는 표를 함께 실었다. 혼자 살펴볼 때는 로컬 실행에 n8n 기본 데이터베이스인 {% include term.html name="SQLite" %}(파일 하나에 저장)로 충분하다. 작은 팀이 함께 쓰면 Docker에 PostgreSQL을 붙이고, 실행이 많이 겹치면 Redis로 작업 대기열을 나누고, 여러 서버를 운영하면 Kubernetes로 컨테이너를 여러 대에 배치한다. 아래로 갈수록 관리할 대상이 늘어난다. 수업이 강조한 건 규모보다 **"멈췄을 때 누가 확인하고 고칠 수 있는가"**에 맞춰 고르라는 것이었다.

## 3. 어디서 만났나

**24회차** 노드 7, n8n 셀프 호스팅을 다룬 선택 심화에서 처음 만났다. 수업 인스턴스나 n8n Cloud처럼 남이 운영해 주는 n8n이 아니라, 내 컴퓨터에 직접 n8n을 띄울 때 쓰는 출발점으로 소개됐다. 함께 나온 볼륨·포트·SQLite·PostgreSQL 이야기는 "직접 띄우면 데이터 보관과 백업이 내 책임이 된다"는 흐름 안에 있었다.

## 4. 헷갈리는 개념

| 이 용어 | 비슷하지만 다른 것 | 차이 |
| --- | --- | --- |
| 이미지 | 컨테이너 | 이미지는 바뀌지 않는 **견본**이고, 컨테이너는 그 견본으로 띄운 **실행 중인 한 통**이다. 이미지 하나로 컨테이너를 여러 개 띄울 수 있다 |
| 컨테이너 안의 파일 | 볼륨 | 컨테이너 안의 파일은 컨테이너를 지우면 같이 사라진다. 볼륨은 컨테이너 **바깥**에 있어서, 컨테이너를 새로 띄워도 이어 붙여 쓸 수 있다 |
| Docker 컨테이너 | 가상 머신 | 가상 머신은 컴퓨터 한 대를 통째로(운영체제까지) 흉내 낸다. 컨테이너는 바탕 컴퓨터의 운영체제 핵심부를 함께 쓰고 프로그램 쪽만 나눠 담아서 더 가볍게 뜬다 |
| Docker | 파이썬 가상환경 (venv) | 가상환경은 **파이썬 패키지**만 프로젝트별로 나눈다. Docker는 운영체제 위의 파일·라이브러리·실행 프로그램까지 한 통에 담는다 |

## 5. 많이들 오해하는 지점

**ㄱ. "컨테이너 안에서 저장했으니 다음에도 남아 있다"**

수업 자료의 명령에는 `--rm`이 붙어 있다. 컨테이너가 멈추면 컨테이너 자체가 지워진다는 뜻이다. 이때 컨테이너 안에만 써 둔 파일은 함께 없어진다. n8n 데이터가 남는 건 `-v n8n_data:/home/node/.n8n`으로 n8n의 데이터 폴더를 바깥 볼륨에 이어 두었기 때문이다. 이 `-v` 조각을 빼고 띄우면, 만든 워크플로가 컨테이너와 함께 사라질 수 있다.

**ㄴ. "`-p 5678:5678`의 앞뒤 숫자는 같은 걸 두 번 쓴 것이다"**

숫자가 같아서 그렇게 보이지만 가리키는 곳이 다르다. 앞 숫자는 **내 컴퓨터 쪽** 문 번호, 뒤 숫자는 **컨테이너 안쪽** 문 번호다. 내 컴퓨터의 5678번을 다른 프로그램이 이미 쓰고 있다면 앞 숫자만 바꿔 다른 문으로 이을 수 있고, 그때 브라우저 주소도 앞 숫자를 따라 바뀐다. 수업 자료가 화면이 안 열릴 때 먼저 볼 원인으로 "포트 충돌"을 꼽은 것도 이 때문이다.

**ㄷ. "내 컴퓨터에서 돌리니까 안전하다"**

수업 자료가 직접 짚은 오해다. 데이터가 남의 서버가 아니라 내 컴퓨터에 있다는 것만으로 안전하다고 할 수 없다. 그 컴퓨터에 누가 접근할 수 있는지, 볼륨을 백업해 두었는지, n8n에 등록한 API 키 같은 비밀값이 어디에 저장되는지를 따로 점검해야 한다. 셀프 호스팅은 편리함과 함께 **보관·백업·업데이트·장애 대응의 책임**을 내가 가져오는 일이다.
