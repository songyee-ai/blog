## 한 줄 정의

> 공개된 AI 모델을 내려받아 내 컴퓨터 안에서 바로 대화할 수 있게 해 주는 프로그램

---

## 1. 비유로 이해하기

게임기를 떠올려 보자. 게임기에는 **앱스토어**가 있다.

- 스토어에서 게임을 골라 **내려받는다.**
- 받은 게임은 게임기 **저장 공간**에 쌓인다. 목록을 보거나, 정보를 보거나, 지울 수 있다.
- 하나를 골라 **실행**하면 그 게임이 게임기 **메모리**에 올라가 돌아간다. 다 놀았으면 끈다.

Ollama가 하는 일이 딱 이 모양이다. 스토어 자리에 **공개 모델 진열장**(ollama.com 라이브러리)이 있고, 게임 자리에 **AI 모델**이 있다.

{% include figure.html src="/assets/images/term-ollama/seven-commands.svg" alt="Ollama 명령 일곱 개가 어디에 작용하는지 보여 준다. pull은 공개 모델 진열장에서 내 디스크로 모델을 받고, run은 디스크의 모델을 메모리에 올려 대화한다. list, show, rm은 디스크의 모델을 보고 지우고, ps와 stop은 메모리에 올라간 모델을 확인하고 내린다. 태그 끝이 -cloud면 계산이 밖의 서버에서 이루어진다" caption="그림 1. 진열장 → 디스크 → 메모리. 일곱 명령은 이 세 곳 중 하나를 건드린다" %}

그래서 실제로는 이렇다. Ollama는 모델 가중치를 내려받고, 내 하드웨어에 맞는 실행 엔진을 골라 붙이고, 터미널 채팅 창과 HTTP API까지 한 번에 얹어 준다. 인터넷을 끊어도 돌아가고, 요금이 나오지 않고, 입력한 문장이 어느 회사 서버에도 가지 않는 상태를 만들 수 있다. 단, 진열장에 있는 건 회사들이 **가중치를 공개한** 모델(Qwen, Llama, Gemma 등)뿐이다.

## 2. 왜 필요한가

### 원래는 손이 많이 가던 일이다

Ollama 없이 모델을 내 컴퓨터에서 돌리려면 GPU 계산 환경(CUDA) 버전을 맞추고, 모델 파일 경로를 지정하고, 컴파일 옵션을 골라야 했다. Ollama는 그 전부를 **명령 한 줄 뒤로** 숨겼다.

내 노트북 기록으로는 이 정도였다.

| 단계 | 내 기록 |
| --- | --- |
| 설치 | 윈도우용 설치 파일, **1.5GB**, 체감 **약 10분** |
| 모델 받기 | `qwen3:0.6b` **522MB**, **90초** |
| 대화 속도 | **41.7 tok/s** |
| 계산 위치 | **100% CPU** (전용 VRAM이 0MB인 내장 그래픽 노트북이라서) |

### 명령은 일곱 개면 된다

| 명령 | 하는 일 | 게임기로 치면 |
| --- | --- | --- |
| `ollama pull <모델>` | 모델을 내려받는다 | 스토어에서 받기 |
| `ollama run <모델>` | 대화를 시작한다 (없으면 알아서 받는다) | 게임 실행 |
| `ollama list` | 디스크에 받아 둔 목록 (`ls`도 된다) | 설치된 게임 목록 |
| `ollama ps` | 지금 메모리에 올라간 모델과 크기 | 지금 켜진 게임 |
| `ollama stop <모델>` | 메모리에서 내린다 | 게임 끄기 |
| `ollama show <모델>` | 구조와 최대 컨텍스트를 본다 | 게임 정보 |
| `ollama rm <모델>` | 디스크에서 지운다 | 게임 삭제 |

이 중 `ollama ps`가 제일 중요하다. **PROCESSOR** 열에 `100% GPU`가 찍히면 모델이 전부 GPU에 올라간 것이고, `48%/52% CPU/GPU`처럼 찍히면 48%가 CPU 쪽으로 밀려났다는 뜻이다. 조금이라도 밀려나면 속도가 그 지점부터 꺾인다. 나처럼 `100% CPU`라면 애초에 GPU를 못 쓰는 환경이다.

### 속도는 `--verbose`로 잰다

`ollama run <모델> --verbose`로 실행하면 답이 끝날 때마다 시간 통계가 붙는다. 볼 줄은 셋이다.

| 항목 | 뜻 |
| --- | --- |
| load duration | 모델을 메모리에 올리는 데 걸린 시간 |
| prompt eval rate | 내 입력을 읽는 속도 (프리필) |
| **eval rate** | **답을 만들어 내는 속도** — 체감 속도는 이 줄이 정한다 |

eval rate는 초당 토큰 수다. 사람이 읽는 속도가 대략 초당 대여섯에서 열 토큰이라서 기준은 이렇다.

```
eval rate 15 넘음   → 대화가 답답하지 않다
eval rate 5 아래    → 기다림이 체감된다
```

내 41.7 tok/s는 넉넉히 빠른 쪽이다. 한 가지 주의할 점이 있다. **load duration은 첫 실행에서만 크게 나온다.** 디스크에서 모델을 읽어 올리는 시간이라 두 번째 질문부터는 거의 0이다. 그래서 속도는 첫 응답을 버리고 **두 번째부터** 기록한다.

### 실수하기 쉬운 세 가지

**① 받은 뒤 이름을 확인하고 그 이름으로 실행한다.** 같은 태그를 받아도 기기에 맞는 변종으로 저장될 수 있다. 수업 자료에서는 애플 실리콘 맥에서 `qwen3.5:4b`를 받았더니 `qwen3.5:4b-mlx`라는 이름으로 저장됐고, 원래 이름으로 `run`을 치자 처음부터 다시 받기 시작했다.

```
ollama pull qwen3.5:4b
ollama list                                  # 여기 찍힌 실제 이름을 쓴다
ollama run <확인한 이름> --verbose --think=false
```

**② `--think=false`는 등호로 붙인다.** 띄어 쓰면 `false`가 설정값이 아니라 **질문**으로 넘어가 버린다. 이 옵션은 답 전에 혼잣말처럼 늘어놓는 생각 과정을 끈다.

**③ 기본 컨텍스트는 기기마다 다르다.** Ollama는 쓸 수 있는 메모리에 따라 창 크기를 정한다.

| 쓸 수 있는 메모리 | 기본 컨텍스트 |
| --- | --- |
| 24GiB 미만 | 4K |
| 24~48GiB | 32K |
| 48GiB 이상 | 256K |

내 노트북에서 컨텍스트가 4096으로 잡힌 이유가 이것이다. 실제 값은 `ollama ps`의 CONTEXT 열에서 본다. 바꾸고 싶으면 두 줄짜리 **Modelfile**에 `PARAMETER num_ctx <길이>`를 적어 파생 모델을 만드는 방법이 어디서 돌리든 똑같이 먹힌다.

## 3. 어디서 만났나

**12회차**에서 "내 노트북에도 LLM을 만들 수 있을까?"라는 실습으로 직접 설치했다. 설치와 동작 확인은 Claude Code에게 맡겼는데, 조사 표를 먼저 받아 보니 내 노트북은 전용 VRAM이 없는 내장 그래픽이었다. 그래서 추천받은 4B급보다 더 작은 qwen3:0.6b를 받아 돌렸다.

번역을 시켜 봤더니 결과는 엉망진창이었지만 **반응 속도는 굉장했다.** 작은 모델이 빠르긴 해도 똑똑하지는 않다는 것을 몸으로 느낀 첫 경험이다.

## 4. 헷갈리는 개념

| 이 용어 | 비슷하지만 다른 것 | 차이 |
| --- | --- | --- |
| Ollama | LLM | LLM은 **모델** 자체(게임). Ollama는 그 모델을 받아 돌려 주는 **프로그램**(게임기) |
| Ollama | ChatGPT·Claude 같은 서비스 | 서비스는 회사 서버에서 돈다. Ollama의 일반 모델은 **내 컴퓨터**에서 돈다 |
| `ollama list` | `ollama ps` | list는 **디스크에 받아 둔** 목록, ps는 지금 **메모리에 올라가 도는** 목록 |
| `ollama stop` | `ollama rm` | stop은 메모리에서 **내리기**(파일은 남는다), rm은 디스크에서 **지우기** |

## 5. 많이들 오해하는 지점

**ㄱ. "Ollama로 돌리면 무조건 내 컴퓨터 안에서만 돈다"**

태그 끝에 `-cloud`가 붙은 모델(예: `gpt-oss:120b-cloud`)은 명령도 화면도 똑같지만 **계산은 Ollama의 데이터센터에서** 한다. 블로그에서 명령을 복사하거나 목록에서 무심코 고르는 순간 데이터가 기기를 벗어난다.

알아채는 방법이 있다. 클라우드 모델은 `ollama signin`으로 **로그인을 요구한다.** 내 기기에서 도는 모델은 로그인을 묻지 않으니, 로그인을 묻는다면 그건 밖으로 나가는 길이다.

**ㄴ. "첫 응답 속도가 그 모델의 속도다"**

첫 응답에는 모델을 디스크에서 읽어 올리는 load duration이 섞여 있다. 두 번째부터는 이 시간이 거의 0이 된다. 첫 숫자로 "이 모델은 느리다"고 판단하면 억울한 모델이 생긴다.

**ㄷ. "빠르면 쓸 만하다"**

내 qwen3:0.6b는 41.7 tok/s로 빨랐지만 번역은 엉망이었다. **속도는 모델 크기와 기기가 정하고, 실력은 주로 모델 크기가 정한다.** 작은 모델은 빨리 답하는 대신 지시를 흘리고 형식을 자주 놓친다. eval rate는 "기다릴 만한가"를 알려 줄 뿐, "믿을 만한가"는 알려 주지 않는다.
