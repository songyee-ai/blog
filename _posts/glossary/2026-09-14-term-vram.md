## 한 줄 정의

> 그래픽카드가 따로 달고 있는 전용 메모리. 로컬 LLM이 제 속도로 돌려면 모델이 여기에 다 들어가야 한다

---

## 1. 비유로 이해하기

교실에서 숙제를 한다. 교과서와 공책을 **책상 위에 펼쳐 놓으면** 고개만 숙여서 바로 본다.

그런데 책상이 좁아서 사전을 올릴 자리가 없다. 사전은 복도 **사물함**에 넣어 둬야 한다. 모르는 단어가 나올 때마다 일어나서 복도까지 갔다 와야 한다. 숙제는 끝나긴 하지만, 한 줄 쓰는 데 한참 걸린다.

{% include figure.html src="/assets/images/term-vram/desk-and-locker.svg" alt="8GB VRAM을 책상에 비유하면 짧은 대화는 모델 가중치 4.6GB와 KV 캐시 0.52GB가 모두 책상 위에 들어가지만, 32K 컨텍스트를 가득 채우면 8.8GB가 되어 넘친 부분이 시스템 RAM이라는 사물함으로 밀려나고 속도가 초당 한 자릿수 토큰으로 떨어진다" caption="그림 1. 책상에서 넘친 만큼 사물함을 왕복한다" %}

그래서 실제로는 책상이 **VRAM**(그래픽카드 전용 메모리), 사물함이 컴퓨터 본체의 **RAM**이다. 모델은 단어 하나를 만들 때마다 가중치를 **전부** 읽어야 한다. 가중치가 VRAM에 다 있으면 빠르고, 일부가 RAM으로 밀려나면 매번 그쪽을 왕복하느라 느려진다.

## 2. 왜 필요한가

### 내 기계에 무엇이 들어가나를 정한다

로컬에서 돌릴 수 있는 모델 크기는 사실상 VRAM 용량이 정한다. 필요한 양은 이렇게 어림한다(4비트 기준).

```
필요 메모리 ≈ 파라미터 수(B) × 0.5GB + KV cache + 약 0.75GB
```

수업 자료가 정리한 사다리는 이렇다.

| VRAM | 돌릴 수 있는 범위 (4비트 기준) |
| --- | --- |
| 8GB | 8B급을 짧은 컨텍스트로 겨우 |
| 12GB | 14B급까지, 컨텍스트도 넉넉히 |
| 16GB | 20B급, 또는 8B를 긴 컨텍스트로 |
| 24GB | 30~35B급 (약 21.7GB) |
| 32GB | 35B를 긴 컨텍스트로, 또는 70B 진입 |
| 48GB 이상 | 70B급을 긴 컨텍스트와 함께 |

### 가중치만 보고 계산하면 틀린다

책상에는 교과서(가중치)만 올라가는 게 아니다. 대화가 길어질수록 **KV 캐시**라는 메모 더미가 옆에 쌓인다. 8B급 모델 기준 수업 자료의 숫자다.

| 컨텍스트 | KV 캐시 | 가중치 4.6GB와 합치면 |
| --- | --- | --- |
| 4K | 0.52GB | 약 5.1GB |
| 32K | 4.19GB | 약 8.8GB |
| 128K | 16.78GB | 약 21.4GB |

4.6GB 파일이니 8GB 카드면 넉넉하다고 생각하기 쉽다. 하지만 32K를 가득 채우면 8.8GB로 이미 넘친다. **사다리의 칸은 가중치와 캐시가 함께 들어가야 하는 자리**다.

### 넘치면 멈추지 않고 느려진다

칸을 넘치면 프로그램이 죽는 대신, 못 들어간 층이 CPU와 RAM으로 넘어간다. 이걸 **CPU 오프로딩**이라고 한다.

```
전부 VRAM에 있을 때:  초당 수십 ~ 백 토큰
넘치기 시작하면:      초당 한 자릿수 토큰
```

대화는 어떻게든 되지만, 에이전트가 도구를 여러 번 부르며 돌아야 하는 일에는 치명적이다. Ollama에서는 `ollama ps`의 PROCESSOR 열로 확인한다. `100% GPU`면 전부 책상 위, `48%/52% CPU/GPU`처럼 찍히면 일부가 사물함에 있다는 뜻이다.

### 맥은 책상과 사물함이 한 방이다

Apple Silicon 맥은 CPU와 GPU가 **통합 메모리** 하나를 나눠 쓴다. 따로 된 VRAM이 없고, 장착된 RAM이 곧 예산이다.

다만 전부 쓰지는 못한다. GPU 몫으로 권장되는 건 통합 메모리의 **대략 3분의 2에서 4분의 3**이다. 64GB 맥이라면 40GB대 중반이 현실적인 상한이다.

### 내 노트북의 VRAM은 0MB였다

Ollama를 깔고 Claude에게 하드웨어를 조사시켰다. 내 노트북(LG 그램, Intel Iris Plus 내장 그래픽)은 **전용 VRAM이 0MB**였다. 그래픽 메모리를 전부 시스템 RAM에서 빌려 쓰는 구조다.

처음에는 VRAM이 1,024MB라고 보고됐는데, 이건 공유 메모리의 기본 할당치일 뿐이었다. 실제로 qwen3:0.6b를 올려 보니 `ollama ps`에 **100% CPU**로 찍혔다. 책상 없이 사물함 앞에 서서 숙제를 한 셈이다. 그래도 모델이 워낙 작아서 초당 41.7토큰이 나왔다.

## 4. 헷갈리는 개념

| 이 용어 | 비슷하지만 다른 것 | 차이 |
| --- | --- | --- |
| VRAM | RAM | VRAM은 **그래픽카드 안**의 전용 메모리, RAM은 **본체**에 꽂힌 메모리. 모델은 VRAM에 다 들어가야 제 속도가 난다 |
| VRAM | 통합 메모리 | 통합 메모리는 CPU와 GPU가 **한 덩어리를 나눠 쓰는** 방식(Apple Silicon). GPU 몫은 대략 3분의 2~4분의 3 |
| 전용 VRAM | 공유 그래픽 메모리 | 내장 그래픽은 RAM 일부를 빌려 쓴다. 숫자가 보고돼도 따로 달린 메모리가 아니다 |
| VRAM | 디스크 | 디스크는 모델 파일을 **보관**하는 곳, VRAM은 모델을 **펼쳐 놓고 쓰는** 곳 |

## 5. 많이들 오해하는 지점

**ㄱ. "RAM이 16GB면 VRAM도 16GB다"**

다른 물건이다. 내 노트북은 RAM이 15.7GB인데 전용 VRAM은 0MB였다. 사물함이 넓다고 책상이 넓어지지 않는다.

예외는 Apple Silicon 맥처럼 통합 메모리를 쓰는 기기다. 그때도 RAM 전부가 아니라 3분의 2에서 4분의 3 정도만 GPU 몫이다.

**ㄴ. "모델 파일이 VRAM보다 작으면 들어간다"**

파일은 교과서일 뿐이다. 대화가 길어지면 KV 캐시가 쌓인다. 4.6GB 모델도 32K를 가득 채우면 8.8GB가 되어 8GB 카드를 넘친다. 8GB 카드에서 8B 모델을 쓰려면 컨텍스트를 4K~8K로 두거나 캐시를 양자화해 줄여야 한다.

**ㄷ. "창을 크게 열어 두기만 해도 메모리를 먹는다" (또는 "안 먹는다")**

**엔진마다 다르다.** 수업 자료의 맥(MLX 변종)에서는 컨텍스트 설정을 4,096에서 262,144까지 64배로 키워도, 짧은 문장만 넣으면 `ollama ps`의 SIZE가 3.4GB 그대로였다. 채운 만큼만 쌓였다.

반면 Ollama의 기본 엔진은 모델을 올릴 때 설정한 길이만큼 KV 캐시 자리를 **미리 잡아 둔다.** 이쪽에서는 창을 크게 열기만 해도 그만큼 메모리를 문다. 설정값만 바꿔 가며 SIZE가 따라 움직이는지 재 보면 내 기기가 어느 쪽인지 알 수 있다.
