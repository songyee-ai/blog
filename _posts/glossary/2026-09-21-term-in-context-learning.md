## 한 줄 정의

> 예시와 문제를 한꺼번에 입력에 넣어 주면, 모델이 가중치를 바꾸지 않고 그 자리에서 규칙을 읽어 답하는 방식

---

## 1. 비유로 이해하기

수학 시험지를 받았는데 맨 위에 처음 보는 기호가 있다. `2 ◆ 3 = 7`, `4 ◆ 1 = 9`, `5 ◆ 2 = 12`. 그리고 네 번째 줄에 `3 ◆ 4 = ?`가 적혀 있다.

선생님이 ◆가 무슨 뜻인지 가르쳐 준 적은 없다. 그래도 예시 세 줄을 보면 "앞 숫자에 2를 곱하고 뒤 숫자를 더하는구나" 하고 알아챈다. 그래서 답은 10이다.

시험이 끝나면 ◆ 규칙은 잊어버린다. 다음 시험지에 ▲가 나오면 또 그 시험지의 예시를 보고 새로 알아낸다. 그렇다고 아무것도 안 배운 건 아니다. **예시 몇 줄에서 규칙을 알아채는 요령**은 그동안 문제를 많이 풀면서 몸에 붙었다.

맥락 내 학습이 이 시험지 풀기다. 예시(훈련 행)와 문제(답을 모르는 행)를 한 장에 같이 받고, 한 번 읽어서 답을 낸다.

{% include figure.html src="/assets/images/term-in-context-learning/one-pass.svg" alt="왼쪽 보통의 학습은 훈련 자료로 모델 가중치를 여러 번 고친 다음 새 문제를 넣는다. 오른쪽 맥락 내 학습은 예시 행과 문제 행을 한 입력에 함께 넣고 한 번 계산해 답을 낸다. 가중치는 그대로이고, 답을 낸 뒤 예시는 잊힌다" caption="그림 1. 보통의 학습은 가중치를 고치고, 맥락 내 학습은 입력만 바꾼다" %}

실제로는, 모델 안의 숫자({% include term.html name="파라미터" %}, 가중치)는 한 개도 바뀌지 않는다. 바뀌는 것은 **입력**뿐이다. 모델은 입력에 들어온 예시들 사이의 관계를 계산 한 번에 읽고, 그걸 문제 행에 적용한다. 계산이 끝나면 예시는 입력과 함께 사라진다.

## 2. 왜 필요한가

### 자료가 스무 줄뿐이면 학습이 잘 안 된다

보통의 머신러닝은 "학습 → 예측" 두 단계다. 훈련 자료로 모델을 여러 번 고친 뒤에 새 문제를 넣는다. 그런데 자료가 몇십 줄뿐이면 고칠 거리가 너무 적다.

17회차 실습 표(유방암 자료, 씨앗 세 번 평균)에서 스무 줄로 비교한 값은 이랬다.

| 방법 | 학습 단계 | AUC (20줄) |
| --- | --- | --- |
| TabICL (맥락 내 학습) | 없음 — 표를 통째로 넣고 한 번 계산 | 0.9847 |
| 랜덤 포레스트 | 스무 줄로 실제 학습 | 0.9813 |
| 그래디언트 부스팅 | 스무 줄로 실제 학습 | 0.500 |

TabICL은 학습을 한 번도 안 돌렸는데 랜덤 포레스트와 점수가 나란했다. 눈여겨볼 건 점수 차가 아니라 **준비 단계가 통째로 빠졌다**는 점이다.

그래디언트 부스팅의 0.500은 동전 던지기와 같은 값이다. 나무를 가를 때 "잎 하나에 최소 몇 개는 남아야 한다"는 기본값이 20인데, 자료가 딱 20줄이니 어디서도 가를 수가 없었다. 나무가 한 번도 안 갈라져 모든 줄에 같은 점수를 낸 것이다. 오류 메시지는 하나도 없었다.

### 그럼 TabICL은 언제 배웠나

미리, 아주 많이 배웠다. 다만 진짜 업무 표가 아니라 **가짜 표 수백만 장**으로 배웠다.

1. 규칙을 무작위로 하나 지어낸다 (예: "첫째 열 × 셋째 열이 어떤 값을 넘으면 양성")
2. 그 규칙으로 표를 몇십 줄 찍어 낸다
3. 일부를 예시로, 나머지를 문제로 보여 주고 답을 맞히게 한다
4. 규칙을 바꿔 가며 수백만 번 되풀이한다

그러면 모델이 익히는 건 특정 규칙이 아니라 **"몇 줄을 보고 규칙을 찾아내는 요령"** 그 자체다. 시험지 비유에서 "예시 보고 ◆ 알아채기"가 몸에 붙은 것과 같다. 이렇게 넓게 미리 배워 두고 내 자료는 다시 안 배우는 모델을 {% include term.html name="기반 모델" %}이라고 부른다.

규칙을 지어낼 때 **단순한 규칙이 더 자주** 나오게 해 두었다는 점도 중요하다. 그래서 모델은 여러 설명이 가능할 때 단순한 쪽을 고르는 버릇을 갖게 된다. 스무 줄에 딱 맞는 복잡한 규칙은 수없이 많고 대부분 새 자료에서 틀린다. 줄이 적을수록 이 버릇이 {% include term.html name="과적합" %}을 막아 준다.

### 공짜는 아니다 — 표가 커지면 느려진다

맥락 내 학습은 답을 낼 때마다 **표 전체를 다시 읽는다.** 미리 요약해 둔 모델이 따로 없기 때문이다.

| 훈련 행 수 | 걸린 시간 |
| --- | --- |
| 20줄 | 6.2초 |
| 200줄 | 12.5초 |

행이 늘면 한 번에 읽을 양이 늘어 시간도 같이 는다. 입력에 담을 수 있는 양에도 한계가 있다({% include term.html name="컨텍스트 윈도우" %}). 그래서 이 방식이 빛나는 자리는 자료가 몇십 줄뿐인 곳이다.

### LLM 프롬프트의 예시와 같은 발상

챗봇에게 이렇게 쓰는 것도 맥락 내 학습이다.

```text
사과 → 과일
당근 → 채소
딸기 → 과일
오이 → ?
```

{% include term.html name="프롬프트" %}에 예시 세 줄을 넣었을 뿐인데, {% include term.html name="LLM" %}은 "과일/채소로 나누는 문제구나"를 알아채고 "채소"라고 답한다. TabICL은 이 방식을 글 대신 **표의 행**에 옮긴 것이다. 입력 안의 여러 조각 사이 관계를 한 번에 보는 {% include term.html name="트랜스포머" %} 구조가 두 경우 모두를 가능하게 한다.

## 3. 어디서 만났나

**17회차**에서 AI를 쓰는 갈래 여덟 개를 훑을 때, 시계열·표 자료를 다루는 쪽에서 나왔다. 기반 모델과 {% include term.html name="제로샷" %} 예측 이야기 바로 뒤에, "표 한 장을 통째로 입력에 넣는다"는 TabICL이 소개됐고 이름의 ICL이 맥락 내 학습의 약자라는 설명이 붙었다. 스무 줄에서 세 방법을 나란히 비교한 표가 이 용어의 값어치를 보여 주는 자리였다.

## 4. 헷갈리는 개념

| 이 용어 | 비슷하지만 다른 것 | 차이 |
| --- | --- | --- |
| 맥락 내 학습 | 보통의 학습(훈련) | 학습은 가중치를 고쳐 규칙을 모델에 **새긴다.** 맥락 내 학습은 가중치를 그대로 두고 입력에서 규칙을 **읽기만** 한다 |
| 맥락 내 학습 | 제로샷 | 제로샷은 "내 자료로 학습 단계 없이 바로 답한다"는 뜻. 맥락 내 학습은 그걸 해내는 한 방법으로, 예시를 입력에 같이 넣는다 |
| 맥락 내 학습 | 기반 모델 | 기반 모델은 넓게 미리 배워 둔 **모델**. 맥락 내 학습은 그 모델을 **쓰는 방식** |
| 맥락 내 학습 | 미세 조정(fine-tuning) | 미세 조정은 내 자료로 가중치를 조금 더 고친다. 끝나도 모델에 남는다. 맥락 내 학습은 남는 게 없다 |

## 5. 많이들 오해하는 지점

**ㄱ. "맥락 내 학습: 데이터 사이의 규칙을 찾아내 학습"**

"데이터 사이의 규칙을 찾는다"는 부분은 맞다. 모델은 예시 행들 사이의 관계를 보고 규칙을 알아낸다. 틀린 곳은 "학습"이라는 말이 주는 느낌이다. 이름에 학습이 들어 있지만, 이 과정에서 모델 안에 새로 새겨지는 것은 **하나도 없다.** 가중치는 한 자리도 안 바뀐다. 그 자리에서 규칙을 읽어 답을 내고, 계산이 끝나면 잊는다. 같은 표로 다시 물으면 모델은 처음부터 다시 읽는다. ◆ 기호 시험지를 풀고 나서 ◆를 외워 두지 않는 것과 같다.

**ㄴ. "학습을 안 하니까 이 모델은 아무것도 안 배운 모델이다"**

내 자료로 학습을 안 할 뿐이다. 모델은 미리 가짜 표 수백만 장으로 오래 배웠다. 거기서 배운 건 특정 답이 아니라 규칙을 찾는 요령이다. "학습이 없다"는 말은 **내가 쓸 때** 학습 단계가 없다는 뜻이다.

**ㄷ. "예시를 많이 넣을수록 공짜로 더 좋아진다"**

넣는 양이 늘면 매번 읽어야 할 양도 는다. 20줄에 6.2초던 것이 200줄에는 12.5초가 됐다. 입력 길이의 한계도 있다. 게다가 200줄쯤 되면 평범한 방법들도 비슷하게 따라온다. 자료가 넉넉하면 원래 쓰던 도구로 돌아가는 편이 낫다.
