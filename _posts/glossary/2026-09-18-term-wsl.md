## 한 줄 정의

> Windows 컴퓨터 안에서 진짜 Linux를 함께 돌리는 장치. Linux에서만 도는 도구를 Windows에서 쓰게 해 준다

---

## 1. 비유로 이해하기

우리 집에 외국에서 온 사촌이 머무를 **방 하나**를 새로 들였다고 해 보자.

- 그 방 안에서는 **사촌네 나라 말**만 통한다. 사촌이 가져온 보드게임도 그 방 안에서만 할 수 있다.
- 방과 거실 사이에 **문**이 있어서 물건을 건네줄 수는 있다. 하지만 거실에 둔 장난감을 매번 방 안으로 들고 가서 놀면 번거롭고 느리다. 그 방에서 쓸 건 처음부터 방 안에 두는 게 편하다.
- 거실에 있던 내 **일기장은 방 안으로 저절로 따라 들어가지 않는다.** 방 안에서 쓸 일기장은 따로 한 권 있어야 한다.
- 방을 들이는 공사는 한 번이면 된다. 대신 방 안의 가구는 새로 채워야 한다.

WSL은 이 방이다.

{% include figure.html src="/assets/images/term-wsl/linux-room.svg" alt="Windows 컴퓨터 안에 Linux 방인 Ubuntu가 들어 있다. Windows 쪽에는 C 드라이브 폴더와 Windows용 Claude Code가 있고, Linux 방에는 home 폴더와 따로 설치한 Claude Code, 그리고 Colab CLI가 있다. 두 쪽은 wsl.localhost 경로라는 문으로 파일을 주고받는다. Colab CLI는 Linux 방 안에서만 돌며 거기서 구글 코랩의 T4 GPU를 빌린다. 설치는 관리자 터미널에서 wsl --install 한 줄이다" caption="그림 1. Windows 안에 Linux 방이 하나. 도구도 설정도 방마다 따로다" %}

실제로는, Windows가 Linux(보통 Ubuntu)를 속에 함께 띄워서, Linux용 명령과 프로그램을 Windows 컴퓨터에서 그대로 돌리게 해 주는 기능이다. 파일 폴더도, 설치한 도구도, 도구의 설정도 Windows 쪽과 Linux 쪽이 따로 있다.

## 2. 왜 필요한가

### Linux에서만 도는 도구가 있다

16회차에서 구글 코랩의 GPU를 빌리는 도구가 두 가지 나왔다. 둘 다 구글이 공개한 것이고, 에이전트가 남의 기계를 빌려 계산을 돌리게 해 준다는 점은 같다.

| 쓰는 컴퓨터 | 붙잡는 도구 | GPU는 누가 고르나 |
| --- | --- | --- |
| macOS, Linux | Colab CLI (`colab` 명령) | 명령에 `--gpu T4`를 붙인다 |
| Windows | Colab {% include term.html name="MCP" %} | 브라우저에서 코랩 노트를 열고 런타임을 T4로 **직접** 바꾼다 |

{% include term.html name="CLI" %} 쪽은 공식 문서가 지원 범위를 못 박아 두었다. 지금은 Linux와 macOS만 되고 Windows는 안 된다는 것이다. 그래서 Windows에서 고르는 길은 둘이다.

- **Colab MCP로 간다.** 에이전트 설정 파일에 서버를 등록하고(Python, {% include term.html name="Git" %}, uv가 필요하다), 브라우저에 열어 둔 코랩 노트를 에이전트가 옆에서 몬다. 무엇이 도는지 눈으로 보이는 게 장점이다.
- **WSL을 깔고 그 안에서 CLI를 쓴다.** 터미널에서 세션을 직접 빌리니 브라우저가 필요 없다.

```bash
# Linux 쪽 터미널에서
uv tool install google-colab-cli
colab new -s room --gpu T4
colab status -s room      # 여기에 T4가 찍히면 기계를 받은 것
```

수업은 그날 실습만 보면 MCP 쪽이 걸음이 적다고 했다. WSL은 앞으로 Linux를 전제로 만든 도구를 자주 만날 때 값을 한다.

### 설치는 한 줄

**관리자 권한으로 연** 터미널(PowerShell)에서 이렇게 친다.

```powershell
wsl --install
```

다시 켜고 나면 Ubuntu 터미널을 열 수 있다. 그 안이 Linux 방이다.

### 폴더가 두 군데 있다

| 어디 | Linux에서 보이는 경로 | Windows 탐색기에서 보이는 경로 |
| --- | --- | --- |
| Linux 방 안 (홈 폴더) | `/home/<이름>/` | `\\wsl.localhost\Ubuntu\home\<이름>\` |
| Windows 쪽 C 드라이브 | `/mnt/c/Users/<이름>/` | `C:\Users\<이름>\` |

두 쪽 다 보이긴 하지만, **Linux 도구로 작업할 파일은 Linux 홈 안에 두는 게 훨씬 빠르다.** 문 너머의 파일을 매번 건너가서 읽는 셈이기 때문이다. 내 작업 기록에는 WSL 안의 작업 폴더를 Windows와 분리해 따로 두었더니 파일 접근이 10배 빨랐다고 적혀 있다.

`python`이나 `colab` 같은 명령을 어디서 찾을지 정하는 {% include term.html name="PATH" %}도 두 쪽이 따로다. Windows에 깔린 프로그램이 Linux 터미널에서 똑같이 불린다고 기대하면 안 된다.

### VS Code는 방 안으로 연결한다

VS Code는 Windows에 깔려 있어도 **WSL 연결(Remote-WSL 확장)**로 Linux 방 안에 들어가 작업할 수 있다. 창은 Windows에 뜨지만 터미널과 파일은 Linux 쪽 것이 열린다. 왼쪽 아래에 WSL에 연결됐다는 표시가 뜨면 방 안에 들어온 것이다.

### Claude Code도 방 안에 따로 산다

Windows에 Claude Code를 깔아 두었어도 Ubuntu 안에서는 **다시 설치해야** 한다. 그리고 두 Claude Code는 서로 다른 프로그램처럼 움직인다.

- 설정 파일과 `CLAUDE.md`가 따로다. 나는 Windows 쪽 규칙 중 개인 규칙만 골라 WSL 쪽에 새로 적었다.
- 대화 기록(세션)도 따로 쌓인다. Windows 쪽 대화를 Ubuntu 쪽에서 이어 갈 수는 없다.

## 4. 헷갈리는 개념

| 이 용어 | 비슷하지만 다른 것 | 차이 |
| --- | --- | --- |
| WSL | 가상 머신(VM) | 둘 다 컴퓨터 안에 다른 운영체제를 띄운다. WSL은 Windows와 파일·터미널이 이어지도록 만든 Linux 전용 장치다 |
| WSL | {% include term.html name="가상환경" %} | 가상환경은 Python 패키지만 프로젝트별로 나눈다. WSL은 운영체제를 통째로 하나 더 둔다 |
| Colab CLI | Colab MCP | CLI는 터미널에서 세션을 직접 빌린다(Linux·macOS). MCP는 브라우저에 연 코랩 노트를 에이전트가 몬다(Windows 가능) |
| `google-colab-cli` | `colab-cli` | 앞의 것이 구글 공식 도구(명령 `colab`)다. 뒤의 것은 이름만 비슷한 다른 사람의 도구로, GPU 실행 기능이 없다 |

## 5. 많이들 오해하는 지점

**ㄱ. "Ubuntu만 깔면 준비 끝이다"**

내가 딱 이렇게 생각했다. 수업 시간에 PowerShell을 열어 Ubuntu를 깔고, 그 안에 Claude Code까지 설치했다. 그런데 그다음 단계를 수업 시간 안에 따라가지 못했다.

방을 들인 것과 방 안에서 일할 수 있게 된 것은 다른 일이었다. 9월 19일에 Claude의 도움을 받아 나머지를 마쳤는데, 남아 있던 일이 이만큼이었다.

- VS Code를 WSL에 연결해 Linux 방 안에서 작업하게 하기
- Linux 쪽에 Colab CLI를 깔고 구글 계정 인증하기
- 무료 등급에서 T4 GPU를 실제로 받아 오는지 확인하기

`wsl --install`은 공사의 시작이지 끝이 아니다.

**ㄴ. "이름이 비슷하면 같은 도구다"**

처음에 Linux 쪽에 `colab-cli`라는 패키지를 먼저 깔았다. 이름은 그럴듯했지만 구글이 만든 것이 아니었고, 노트북 파일을 주고받는 도구일 뿐 **GPU에서 코드를 돌리는 기능이 없었다.** 이것을 지우고 구글 공식 `google-colab-cli`(명령은 `colab`)를 다시 깔았다. 수업 자료의 설치 줄을 글자 그대로 따라야 하는 이유다.

**ㄷ. "Windows에 깔린 Claude Code 설정이 WSL에도 적용된다"**

아니다. Ubuntu 안의 Claude Code는 새로 깐 별개의 프로그램이라 설정, `CLAUDE.md`, 스킬, 대화 기록이 모두 따로다. Windows 쪽에서 정해 둔 규칙을 WSL 쪽에서도 쓰려면 옮겨 적거나 연결해 줘야 한다.
