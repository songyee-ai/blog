## 한 줄 요약

> OpenClaw는 내 컴퓨터에 켜 둔 게이트웨이가 여러 채널의 메시지를 받아 에이전트에게 넘기는 개인 비서다. 대화 한 번이 남긴 파일을 직접 비교해 보니, 답변 문장보다 기록 파일이 무슨 일이 있었는지를 더 정확히 말해 줬다.

---

## 1. 오늘 배운 것

24회차의 n8n은 사람이 그린 순서대로 도는 워크플로였고, 26회차에는 에이전트를 여럿 두는 구조를 재 봤다. 오늘은 방향이 또 달랐다. **늘 켜져 있으면서 메시지가 오면 일하는 비서**를 내 컴퓨터에 직접 설치했다. 채팅창에 부탁하면 파일을 찾아 읽고, 휴대폰 메신저로 말을 걸 수도 있고, 정해 둔 시각에 알아서 일을 한다.

실습은 설치, 대화 한 번이 남긴 파일 비교, 휴대폰 메신저 연결, 사용량 보기, 예약 작업 순서였다. 노드마다 되풀이된 건 두 가지였다. 일이 끝났는지는 기록으로 확인한다는 것, 그리고 기능 하나가 늘 때마다 **누가 말을 걸 수 있고, 어디까지 손댈 수 있는지**를 따로 정한다는 것.

> **오늘의 핵심 한 문장**
> 켜 두는 에이전트는 편한 만큼 문이 많다. 문마다 **누가 들어오나, 들어와서 무엇을 만지나, 바깥에서 온 쪽지를 그대로 따르나**를 정하고, 일이 끝났는지는 답변이 아니라 기록으로 본다.

| 순서 | 무엇에 답하는가 |
| --- | --- |
| OpenClaw와 게이트웨이 | 메시지는 어디로 들어와 어디로 가나 |
| 설치·온보딩과 두 인증 경로 | 무엇으로 모델을 부르고, 돈은 어떻게 나가나 |
| 세션 기록 읽기 | 대화 한 번은 무엇을 남기나 |
| Telegram과 페어링 | 휴대폰에서 누가 말을 걸 수 있나 |
| 보안의 세 경계 | 무엇을 따로따로 정해야 하나 |
| pi와 멀티에이전트 | 코어는 어디까지이고, 역할은 어떻게 나누나 |
| 모니터링·자동화·확장 | 얼마나 쓰는지, 언제 저절로 일하는지, 무엇을 더 붙일 수 있나 |
| 왜 필요한가 | 앞으로 무엇을 먼저 보게 되나 |

### 1-1. OpenClaw와 게이트웨이 — 학교 행정실

학교 행정실에는 하루 종일 우편물, 전화, 방문 손님이 들어온다. 행정실 선생님은 그걸 직접 처리하지 않고 "이건 3학년 담임 선생님께", "이건 보건실로" 하고 나눠 보낸다. 행정실이 문을 닫으면 아무것도 전달되지 않는다.

그래서 실제로는 **{% include term.html name="OpenClaw" %}에서 행정실 노릇을 하는 게 늘 켜져 있는 {% include term.html name="게이트웨이" %}(Gateway)다.** 브라우저 대화창이든 휴대폰 메신저든 어느 문(채널)으로 들어온 말이든 일단 여기를 지나고, 여기서 "이 대화는 어느 세션으로, 어떤 도구를 쓸 수 있게" 정해진 뒤 에이전트가 일을 시작한다. 행정실 장부가 하나이듯, 어느 말이 어디로 갔는지도 한곳에 남는다.

{% include figure.html src="/assets/images/openclaw-gateway/gateway-flow.svg" alt="OpenClaw의 메시지 흐름. 왼쪽에서 WebChat, 터미널 채팅 화면, Telegram 세 채널의 메시지가 가운데 게이트웨이로 들어간다. 게이트웨이는 내 컴퓨터의 127.0.0.1 포트 18789에서 열려 있고, 받을 세션과 도구를 정해 오른쪽의 에이전트 실행 부분으로 넘긴다. 에이전트는 모델을 부르고 도구를 실행하며, 대화 기록은 에이전트별 SQLite 파일에 쌓인다. 아래에는 Telegram만 페어링 승인을 거친다고 적혀 있다" caption="그림 1. 문은 여러 개, 행정실은 하나 — 어느 채널로 들어와도 같은 게이트웨이를 지난다" %}

이 도구는 이름이 세 번 바뀌었다. WhatsApp 게이트웨이로 출발한 Warelay, 바닷가재 마스코트와 함께한 Clawdbot, 상표 문제로 바꾼 Moltbot을 거쳐 2026년 1월 30일 지금 이름이 됐다. 자료를 찾을 때 예전 이름도 함께 검색해야 옛 기록을 놓치지 않는다는 점이 실용적인 팁이었다.

### 1-2. 설치·온보딩과 두 인증 경로 — 카드를 맡길까, 내 정기권을 쓰게 할까

심부름을 시킬 때 두 가지 방법이 있다. 내 카드를 직접 쥐여 주면 쓴 만큼 카드에서 나간다. 아니면 내가 이미 끊어 둔 정기권을 쓰게 하면, 돈은 따로 안 나가지만 정기권의 한도 안에서만 쓸 수 있다.

그래서 실제로는 **OpenClaw가 모델을 부르는 길은 API 키를 직접 들고 부르는 방식(종량 과금)과, 이미 로그인해 둔 Claude Code를 거쳐 부르는 방식(구독 한도에서 차감) 두 가지다.** 나는 두 번째(claude-cli)를 골랐다. 이 차이는 나중에 사용량 화면의 숫자 뜻까지 바꾼다. 키 쪽은 "쓴 돈", 구독 쪽은 "남은 한도 비율"이다.

설치 뒤에는 온보딩(처음 설정을 대화형으로 받는 과정)과 함께 게이트웨이를 {% include term.html name="데몬" %}으로 띄웠다. 데몬은 터미널 창을 닫아도 뒤에서 계속 도는 서비스다. 그리고 바로 채널을 붙이지 말고 진단 명령(`doctor`)과 상태 명령(`gateway status`)부터 보라고 했다. 마지막 줄의 "성공"만 보지 말고 남은 경고를 그대로 읽으라는 당부도 있었다.

새 연습 폴더 안에서 설치해도 OpenClaw의 설정과 자격 증명은 그 폴더가 아니라 홈 폴더 `~/.openclaw/`에 쌓인다. 책상을 하나 새로 들여놓아도 열쇠는 여전히 집 현관 열쇠고리에 걸리는 셈이라, **새 폴더가 울타리가 되어 주지는 않는다.** 그래서 수업용 계정과 키만 쓰라고 했다.

### 1-3. 세션 기록 읽기 — "숙제 했어요"와 실제 공책

엄마가 "숙제 했니?" 하고 물으면 아이는 "했어요"라고 답한다. 그런데 진짜 했는지는 공책을 펼쳐 봐야 안다. 말과 공책은 다른 곳에 있다.

그래서 실제로는 **세션 기록에서 모델이 말한 문장과, 모델이 요청한 도구 호출과, 실제로 실행된 결과는 서로 다른 줄에 저장되고, 일이 끝났는지는 결과 줄로 판단한다.** 호출 줄과 결과 줄은 같은 `toolCallId`로 짝지어진다. 내 실습에서도 에이전트 답변에는 "30개 항목은 해당 없어 건너뜀"이라는 숫자가 있었는데, bash에서 직접 친 원래 진단 출력에는 그런 숫자가 없었다(2절). 25회차의 {% include term.html name="실행 궤적" %}을 한 대화 단위로 들여다보는 셈이다.

기록이 어디 남는지도 정리했다. 설정은 `openclaw.json` 하나, 대화 기록과 에이전트 상태는 에이전트마다 따로 있는 {% include term.html name="SQLite" %} 파일, 오래 남길 메모는 워크스페이스의 `MEMORY.md`와 `memory/` 폴더다. 세 곳은 역할이 다르다.

### 1-4. Telegram과 페어링 — 처음 온 친구는 엄마 확인부터

친구가 우리 집 초인종을 처음 누르면, 내가 바로 문을 열기 전에 엄마가 "누구니?" 하고 먼저 확인한다. 엄마가 "들어와도 돼"라고 한 친구는 다음부터 그냥 들어온다. 확인 안 된 사람이 문 앞에서 아무리 말을 걸어도 대답하지 않는다.

그래서 실제로는 **Telegram 봇을 붙여도 아무나 봇과 대화할 수는 없고, 기본 규칙인 {% include term.html name="페어링" %}에서는 처음 말을 건 계정이 기다리는 목록에 올라가고, 주인이 터미널에서 그 계정을 승인한 뒤에야 대화가 열린다.** 승인을 기다리는 코드는 1시간이 지나면 못 쓴다.

봇 토큰은 봇의 신분증 같은 비밀값이라 채팅창·화면 공유·메모 어디에도 남기지 않는다. 명령줄에 직접 넣으면 셸 기록(history)에 남을 수 있다는 경고도 있었다. 규칙은 페어링 말고도 허용 목록(숫자 ID로 정한 계정만)과 전부 허용이 있는데, 전부 허용은 도구를 강하게 묶은 공개 봇에만 맞는다고 했다.

### 1-5. 보안의 세 경계 — 교실 출입, 전화 받을 사람, 쪽지 속 지시

학교에서 지켜야 할 경계를 떠올리면 셋이 따로 있다. 어느 교실에 들어가 무엇을 만져도 되는지(출입 범위), 누구 전화를 받아 줄지(연락 상대), 그리고 복도에서 주운 쪽지에 "교무실 금고를 열어"라고 적혀 있어도 따르지 않기(바깥 쪽지).

그래서 실제로는 **OpenClaw에서도 세 가지를 각각 다른 곳에서 정한다. 파일·명령의 범위는 권한 모드로, 말을 걸 수 있는 계정은 페어링·허용 목록으로, 바깥 내용을 실행으로 옮기기 전의 확인은 읽기 전용 에이전트와 별도 승인으로.**

권한 모드는 계단처럼 읽었다. 맨 아래 read-only는 자기 반 교실에서 책만 볼 수 있다. 쓰는 도구가 아예 없어서 공책에 무언가 적고 싶어도 못 적는다. 한 칸 올라갈 때마다 교실 안에서 할 수 있는 일이 늘고, 명령을 실행하기 전에 "해도 돼요?"를 묻는 상대가 사람에서 모델로 조금씩 옮겨 간다. 맨 위 full은 학교 전체 마스터키라 묻는 절차가 아예 없고, 관리자 권한이 있어야 쓸 수 있다. 칸마다 정확히 어디까지인지는 공식 문서(permission-modes)에 정리돼 있다.

자료를 요약만 하는 일이면 맨 아래 칸에서 시작하고, 고쳐야 할 때만 한 칸 올린다. 바깥 문서·메일·채팅에 섞인 명령 같은 문장이 에이전트를 움직이는 {% include term.html name="프롬프트 인젝션" %}은 "읽어 온 건 판단 재료일 뿐 실행 허가가 아니다"로 막는다.

OpenClaw가 스스로 공개한 보안 권고 세 건도 읽었다. 공통점은 **한 경계의 허락이 다른 경계로 새어 나간 경우**였다. 대화를 허락받은 사람이 기기 등록 권한까지 얻을 수 있었던 일, 명령 이름만 맞으면 인자는 검사 없이 통과하던 일, 모델이 정한 주소로 요청할 때 게이트웨이 자격 증명이 함께 실려 간 일. 모두 고쳐진 뒤 공개된 것이라, 최신 버전을 유지하는 게 첫 번째 방어라고 했다.

### 1-6. pi와 멀티에이전트 — 레고 기본판과 반별 담임

레고 기본판에는 네모난 바닥판과 블록 몇 개만 있다. 바퀴, 창문, 지붕은 필요하면 따로 붙인다. 반대로 완성품 세트는 처음부터 다 붙어 있다.

그래서 실제로는 **pi는 작은 코딩 에이전트 코어이고, OpenClaw는 한때 그 pi를 엔진으로 쓰고 그 위에 메시지를 받는 게이트웨이를 얹어 만든 도구였다.** 지금 OpenClaw는 자체 실행 부분으로 바꿨지만, 코어 위에 채널과 기능을 조립하는 구조는 그대로다. pi는 {% include term.html name="MCP" %} 연결, {% include term.html name="서브에이전트" %}, 예약 실행을 기본으로 담지 않고 바깥에서 붙이게 한다. 도구를 비교할 때 "그 기능이 있나"와 함께 "코어에 있나, 확장에 있나"를 보라는 이야기였다.

{% include term.html name="멀티 에이전트" %}는 학교에 반마다 담임을 두는 모양으로 읽었다. 게이트웨이 하나 안에 에이전트를 여럿 두고, 어느 채널 계정에서 온 메시지를 어느 에이전트가 받을지 바인딩(binding)으로 정한다. 에이전트마다 작업 폴더와 대화 기록이 따로 있고, 기본 메모리도 서로 섞이지 않는다. 어디에도 맞지 않는 메시지는 아무도 받지 않으니, 남은 대화를 받을 담임을 꼭 정해 두라고 했다. 26회차에 본 것처럼, 여기서도 **에이전트 수보다 역할이 겹치지 않게 나누는 게 먼저**였다.

### 1-7. 모니터링·자동화·확장 — 데이터 사용량, 학교 종, 새 문

휴대폰 요금제를 쓰다 보면 이번 달 데이터를 얼마나 썼는지 가끔 확인한다. 그리고 학교 종은 아무도 줄을 당기지 않아도 정해진 시각에 울리지만, 종을 움직이는 기계에 전기가 끊기면 울리지 않는다.

그래서 실제로는 **사용량은 채팅 명령(`/status`, `/usage`)과 명령줄(`openclaw status --usage`, `openclaw models status`)로 보고, 반복 작업은 게이트웨이 안에 든 스케줄러(automations)에 예약한다. 스케줄러는 모델이 아니라 게이트웨이가 돌리는 것이라, 게이트웨이가 꺼져 있으면 예약 시각이 돼도 실행되지 않는다.**

- 반복 시각은 {% include term.html name="cron" %} 표기(분 시 일 월 요일 다섯 칸)로 적는다. `*/5 * * * *`는 5분마다다.
- 한 번만 도는 작업은 끝나면 목록에서 사라지고, 반복 작업은 다음 시각을 단 채 남는다.
- 대화창에서 `/loop 5m …`로도 반복 작업을 만들 수 있다. 명령줄로 만들든 대화창으로 만들든 같은 예약 목록에 올라간다.
- 남겨 둔 반복 작업은 게이트웨이가 켜져 있는 동안 계속 도니, 실습이 끝나면 지운다.

마지막 노드 10은 붙일 수 있는 확장 기능(브라우저 조작, 휴대폰·다른 컴퓨터를 연결해 카메라·위치 쓰기, 음성 대화, 메일함 감시, 모델 페일오버, 스킬 배포처)을 둘러봤다. OpenClaw는 이렇게 연결한 기기도 "노드"라고 부르는데, 수업 단원을 부르는 노드와는 다른 말이다. 기능 하나를 더하면 **닿는 범위, 남는 기록, 허락할 권한**이 함께 늘어난다는 게 공통 주의점이었다. 메일함 감시가 메일을 주 에이전트에 바로 넣지 않고 권한이 가장 작은 읽기 전용 에이전트에게 먼저 넘기는 것도 1-5의 바깥 쪽지 원칙 그대로였다.

### 1-8. 왜 필요한가

앞으로 "에이전트가 다 했대요"라는 말을 들으면, 먼저 **어디에 기록이 남았나**를 물을 것 같다. 오늘 실습에서 답변 문장에는 기록에 없는 숫자가 섞였고, 사실과 다른 설명도 있었다(2절).

그리고 켜 두는 도구를 들일 때는 기능 목록보다 문 목록을 먼저 보게 될 것 같다. 채널 하나, 확장 하나가 늘 때마다 새 문이 생기고, 문마다 누가 들어오고 무엇을 만지는지를 따로 정해야 한다.

### 2-1. 실습 1 — 설치·온보딩·WebChat

| 확인 | 결과 |

| 경고 1 | 게이트웨이가 loopback(127.0.0.1)에만 열려 있음 → 다른 기기 연결 계획이 없어 그대로 둠 |

설치 때 의존 패키지 네 개의 설치 스크립트가 허용 범위 밖이라 실행되지 않았다는 경고가 나왔지만 버전 확인은 정상이었다. `gateway status`에서는 게이트웨이 서비스가 nvm의 Node를 써서, 나중에 Node를 지우거나 올리면 서비스가 깨질 수 있다는 지적도 나왔다.

**말과 결과를 처음 겪은 장면.** 온보딩이 끝난 뒤 채팅 화면에 있는 줄 모르고 `openclaw doctor`를 입력했더니, 명령이 아니라 에이전트에게 보내는 메시지가 됐다. 에이전트는 스스로 `openclaw doctor --lint`를 도구로 실행하고 결과를 풀어서 답했다. 그 답변과 bash에서 직접 친 원래 출력을 나란히 놓으니 이랬다.

| | 원래 출력 | 에이전트 답변 |
| --- | --- | --- |
| 검사 수·경고 수·오류 | 36개·2개·없음 | 같음 |
| 경고 이름 둘 | 있음 | 같음 |
| "30개 항목은 해당 없어 건너뜀" | 이 숫자가 없음 | 답변에만 있음 (확인할 수 없음) |

답변 끝에서 "토큰을 보관함으로 옮길까요?"라고 설정 변경을 제안했지만 답하지 않았다. 터미널 채팅 화면에서 나눈 이 대화는 브라우저 WebChat의 Main Session에도 그대로 떠 있었다. 화면이 달라도 같은 메인 세션으로 이어진다는 뜻이다.

### 2-2. 실습 2 — 대화 한 번이 남긴 파일

WebChat에 짧은 메시지를 보내기 전과 후에 같은 명령으로 파일 목록을 저장하고 `diff`로 비교했다.

```bash
ls -laR --time-style=full-iso ~/.openclaw/agents/main ~/.openclaw/workspace > before.txt
# (WebChat에 짧은 메시지 하나)
ls -laR --time-style=full-iso ~/.openclaw/agents/main ~/.openclaw/workspace > after.txt
diff before.txt after.txt
```

| 위치 | 바뀐 것 |
| --- | --- |
| `agents/main/agent/openclaw-agent.sqlite` | 720,896 → 753,664바이트 (+32KB), 시각 바뀜 |
| 같은 이름의 `-wal`, `-shm` | 시각만 바뀜 |
| `agents/main/sessions/` | 비어 있음, 변화 없음 |
| `workspace/` (`AGENTS.md`, `SOUL.md` 등) | 변화 없음 |

대화 한 번으로 바뀐 곳은 에이전트별 SQLite 파일 세 개뿐이었다. `-wal`은 새로 쓸 내용을 먼저 적어 두는 임시 기록, `-shm`은 그 색인이다. 보내기 전 시각은 터미널 채팅 화면에서 doctor 대화를 한 때라, 그 대화도 같은 파일에 쌓였다는 뜻이다. 워크스페이스는 그대로여서 `MEMORY.md`나 `memory/`는 생기지 않았다.

이 대화의 답변에도 확인할 곳이 있었다. 에이전트는 "컴퓨터를 켜면 저절로 실행됩니다"라고 했지만, 서비스는 WSL 안의 systemd에 등록돼 있어서 윈도우를 켜도 WSL이 시작되기 전에는 게이트웨이가 돌지 않는다. 1-3에서 본 대로 답변 문장은 근거가 아니었다.

`openclaw memory status`로 기억 쪽도 봤다.

| 본 것 | 뜻 |
| --- | --- |
| 임베딩 제공자 OpenAI | 메모 검색용 {% include term.html name="임베딩" %}은 대화 모델(Claude)과 별개로 OpenAI를 쓰도록 잡혀 있음 |
| 색인 0/2 파일 · 0 청크, Dirty yes | 바뀐 내용이 있는데 색인에 하나도 반영 안 됨 |
| 저장 위치 | 색인도 대화 기록과 같은 SQLite 파일 |
| 의미 검색 paused, 전문 검색 unavailable | 지금은 어느 검색도 못 씀 |
| 색인 만드는 명령 | 임베딩 업체를 불러 비용이 들 수 있다고 출력이 직접 경고 → 실행하지 않음 |
| Dreaming 예약 | 매일 새벽 3시(`0 3 * * *`)에 기억을 정리하는 예약이 기본으로 잡혀 있음 |

정리하면 **대화는 SQLite에 쌓였지만 "검색할 수 있는 기억"으로는 아직 하나도 바뀌지 않았다.** 저장과 색인은 다른 단계였다. 나중에 OpenAI 키를 넣으면 이 색인에도 쓰여 종량 과금이 생긴다는 점도 적어 두었다.
