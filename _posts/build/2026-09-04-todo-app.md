## 무엇을 만들었나

> 할 일을 추가·완료·삭제하고 마감일·태그·반복까지 다루는, 내 컴퓨터에서만 도는 할 일 앱. 코드보다 DB 구조를 먼저 받아 표 다섯 개로 설계했고, 데이터는 파일 하나에 저장해 껐다 켜도 남는다.

[6회차 — 데이터베이스]({{ site.baseurl }}/2026/09/04/database-sql-backup/) 수업의 과제다. 할 일을 **추가·조회·완료·삭제**하는 앱이라 {% include term.html name="CRUD" %}의 교과서이고, 데이터가 {% include term.html name="데이터베이스" %}에 저장돼 껐다 켜도 남는지를 눈으로 확인할 수 있다.

바로 앞 작업물인 그루뽑기는 데이터를 클라우드에 두었다. 이번엔 반대로 **내 컴퓨터의 파일 하나**(`data/todo.db`)에 둔다. 인터넷 주소가 없고, 내 컴퓨터에서 서버를 켜야 열린다. 그게 실제로 무슨 뜻인지는 아래 시도 5에서 겪었다.

과제는 세 부분이었다. 1부 PRD와 DB 구조 설계, 2부 로컬에서 돌리기, 3부 같은 앱을 클라우드로 옮기기. **이 글은 1·2부까지다.** 3부는 아직 하지 않았다.

**직접 해보기** → 내 컴퓨터에서만 도는 앱이라 체험 주소는 없다. 저장소를 내려받아 `npm install` → `npm start` 후 브라우저에서 `http://127.0.0.1:5173`

**코드 보기** → [github.com/songyee-ai/todo](https://github.com/songyee-ai/todo)

## 1. 만들기 전 스케치

손그림 대신 **DB 구조도**가 스케치 역할을 했다. 과제가 "코드보다 DB 구조를 먼저 받아라"였기 때문이다.

수업에서 배운 대로 **태그를 넣으니 할 일과 태그가 다대다**가 되어 연결 표(`todo_tags`)가 생겼다. 반복도 표가 하나 더 필요했다. "매주 화·목 분리수거"는 할 일 표 하나로는 담을 수 없어서 **반복 규칙 표가 따로** 생겼다. 이 그림이 맞게 나왔는지 읽고 확정하는 것이 내 몫이었다.

## 2. 만드는 과정 — 프롬프트 기록

### 시도 1 — PRD를 주고 "보안부터 제안해 줘"

수업의 PRD 틀에 내가 넣고 싶은 기능을 채웠다.

- 기본: 추가 · 목록 · 완료 · 삭제, 데이터는 내 컴퓨터의 무료 DB에
- 내가 넣은 것: 깔끔하고 귀여운 디자인, 반복 작성, 마감일, 태그, 오늘 할 일만 보기, 검색
- 규칙: 무료 도구만, 비밀값은 `.env`로, 로그인을 넣는다면 직접 만들지 말고 검증된 라이브러리로

그리고 바로 만들지 말고 순서를 지켜 달라고 했다.

> 먼저 위 PRD로 만들 Todo 앱의 추가 수정이나 보안을 제안해주고. 확정되면 DB 구조(어떤 표·열·관계)를 먼저 설계해서 구조도로 그려 보여 줘.

돌아온 제안 중 몇 가지다.

- **서버를 `127.0.0.1`에만 열기.** 아무 데나 열어 두면 같은 와이파이의 다른 기기가 내 할 일을 볼 수 있다고 했다
- **사용자가 쓴 글은 화면에 글자로만 넣기.** 할 일 제목에 코드 조각을 써 넣어도 실행되지 않게
- **`.env`와 DB 파일은 GitHub에 올리지 않기.** 개인 할 일이 저장소에 올라가면 안 되니까
- **로그인은 넣지 않기.** 내 컴퓨터에서 나 혼자 쓰는 앱에는 공격받을 문만 늘어난다고

질문 창으로 고르는 단계도 있었다. 만드는 방식은 추천받은 "Express + SQLite + 그냥 HTML"을 골랐다. 앞의 2048·벽돌깨기처럼 빌드 도구 없이 파일만으로 된다는 설명이었다. 반복 기능은 선택지가 무슨 뜻인지 헷갈려서, 내가 원하는 화면을 그대로 적었다.

> … 해야할 일을 등록할 때 반복 (매주,매달,특정요일마다 등 월~일 표시로 선택을 한다거나 등)과 일회성인지 체크하는 기능이 있으면 좋을 것 같아. 혹은 더 좋은 아이디어가 있으면 제안해줘.

답은 "그 화면이 원하는 거라면, 저장은 규칙 하나만 해 두고 할 일은 그날그날 꺼내는 방식이 맞다"였다. 거기에 "2주마다"까지 되게 **간격** 칸을 하나 더 두자는 제안을 받았다.

### 시도 2 — DB 구조도 받기

표 다섯 개가 나왔다(그림 1). 표 설계에서 처음 알게 된 것들이다.

| 무엇 | 왜 그렇게 했나 |
| --- | --- |
| 완료를 "했다/안 했다" 대신 **완료한 시각**으로 | "오늘 완료한 일"을 따로 계산할 필요 없이 바로 나온다 |
| 삭제는 지우지 않고 **휴지통 시각**만 적기 | 실수로 지워도 되살릴 수 있다 |
| 마감일은 **`2026-09-04` 같은 글자**로 | 세계 표준시로 바꿔 저장하면 "오늘 할 일"이 하루씩 밀리는 일이 생긴다 |
| 반복 회차는 **규칙 + 날짜 짝이 겹치지 않게** | 앱을 열 때마다 같은 날 회차가 또 생기는 걸 막는다 |

설계를 실제 파일(`db/schema.sql`)로 옮기고, 잘못된 데이터를 일부러 넣어 막히는지까지 확인한 결과를 받았다.

### 시도 3 — "스키마 확정. 서버랑 화면 만들어 줘"

한 줄로 넘겼다. 서버(Express), DB 연결(SQLite), 입력 검사, 화면 세 파일이 만들어졌다. 반복 규칙이 날짜를 제대로 고르는지 확인하는 **테스트 10개**도 같이 생겼다. "매월 31일" 규칙이 2월에는 28일로 맞춰지는지 같은 경우들이다.

### 그 사이 — 검증과 버그

에이전트가 브라우저를 직접 열고 눌러 보면서 문제를 찾았다. 그중 하나는 꽤 심각했다. **할 일을 체크하는 순간 붙여 둔 태그와 중요도가 지워졌다.** 원인은 4-2에 적었다.

고친 뒤에는 서버를 실제로 띄워 요청을 보내 보는 **테스트 10개**를 더 붙였다. 그중 하나가 "체크해도 태그·중요도·마감일이 그대로인가"다. 같은 실수가 다시 나면 바로 걸린다.

### 시도 4 — 색과 서체

처음엔 분홍 파스텔이었는데, 블루 팔레트 이미지를 붙이고 **"톤과 무드만 비슷하게, 모던하고 간결하게"**를 부탁했다. 동그란 알약 모양이 모서리 둥근 사각형으로 바뀌고, 체크 상자와 요일 선택도 같은 모양으로 맞춰졌다.

제목에 한글 세리프 서체를 넣어 달라고 했더니, 확인해 보니 **Noto Serif KR이 이미 컴퓨터에 깔려 있어서** 파일을 넣을 필요가 없었다. 태그는 `수업 · 과제 · 프로젝트 · 블로그 · 개인 · 집안일`로 미리 등록했다. 블루 계열만 6개면 색으로 구분이 안 된다고 해서 샌드·세이지 두 색을 섞었다.

### 시도 5 — 앱 아이콘을 눌렀는데 안 열린다

브라우저의 "앱으로 설치"로 바탕화면에 아이콘을 만들었다. 그런데 아이콘을 눌렀더니 **"사이트에 연결할 수 없음"**이 떴다.

> 너가 말한 서버가 검정색 화면인거야? 항상 같이 켜져 있어야만 열리는거야? 그럼 그 서버는 어떻게 켜?

그렇다는 답이었다. 아이콘은 **주소를 여는 바로가기일 뿐 서버를 켜 주지 않는다.** 식당 문 앞에 도착했는데 가게가 아직 문을 안 연 상태와 같다. 그러니까 실제로는 **화면 뒤에 서버가 따로 돌고 있고**, 그게 켜져 있어야 화면이 열린다.

다음 날 쓴 [7회차 글]({{ site.baseurl }}/2026/09/07/agent-mcp-skill/)에는 세부 작업 내용은 이해하지 못한 상태라고 적었다. 그래도 서버가 무엇인지는 이 질문으로 직접 물어서 답을 들었다.

그래서 켜고 끄는 파일 세 개를 받았다. 서버를 검은 창으로 켜고 브라우저까지 여는 것, 창 없이 서버만 켜는 것, 서버를 끄는 것.

### 9월 9일 — GitHub에 올렸다

개인 데이터(`data/`, `.env`)는 빼고 코드와 표 설계만 [저장소](https://github.com/songyee-ai/todo)에 올렸다.

### 일주일 뒤 점검, 한 달 뒤 수정 — 출석 카드

`수업 QR 출석 하기`를 매주 월~금 반복으로 넣어 두었다. 그런데 이 할 일은 앱에서 한 번도 체크하지 않았다. 앱은 지난 날짜 회차를 **기한 지난 할 일로 보고 빨간 테두리**를 친다.

9월 13일, 화면을 손보고 싶어서 물었다.

> todo 프로젝트 화면을 좀 제대로 만들고 싶은데 어떻게 하면 좋을까?

먼저 돌아온 건 디자인 제안이 아니라 점검 결과였다. 첫 화면을 입력 칸이 다 차지하고, 그때 이미 빨간 출석 카드가 4장이었다. 빨간 카드가 여러 장이면 빨강이 경고로 안 읽힌다는 것. 어디까지 고칠지 정하기 전에 대화가 멈췄다.

한 달 뒤 이 글을 쓰려고 다시 열어 보니, 앱을 켜는 순간 **출석 카드 22장이 한꺼번에** 생기는 상태였다. 그래서 반복 회차 문제만 먼저 고쳤다.

- 지난 날짜에 안 한 **반복** 할 일은 목록 맨 아래에 `놓친 반복 할 일 N건` 한 줄로 접는다
- 펼쳐서 **한 번에 휴지통으로** 보낼 수 있고, 보낸 회차는 다시 생기지 않는다
- **한 번만 하는 할 일**이 기한을 넘긴 건 아직 해야 할 일이라 접지 않고 빨갛게 둔다

고친 뒤 리뷰 에이전트에게 검토를 따로 맡겼다. 막아야 할 버그는 없었고, "펼치기를 누르면 키보드 포커스가 사라진다" 같은 작은 지적 세 개를 반영했다.

## 4. 코드에서 배운 부분

### 4-1. 반복은 규칙만 적어 두고, 할 일은 그날그날 꺼낸다

"매주 화·목 분리수거"를 저장하는 방법은 두 가지다. 1년치 달력 칸에 분리수거를 다 적어 두거나, **냉장고에 "화·목은 분리수거" 메모 한 장**을 붙여 두고 아침마다 그날 칸만 채우거나. 이 앱은 두 번째다.

그래서 실제로는 반복 규칙 표에 한 줄만 저장하고, 앱을 열 때 **오늘까지 필요한 날짜만** 할 일 표에 만든다. 내년 날짜까지 미리 만들어 두지 않으니 데이터가 끝없이 늘지 않고, 규칙을 멈추면 그다음 날짜부터는 생기지 않는다.

```sql
-- 규칙과 날짜의 짝은 겹칠 수 없다
CREATE UNIQUE INDEX IF NOT EXISTS ux_todos_rule_occurrence
  ON todos(repeat_rule_id, occurrence_date)
  WHERE repeat_rule_id IS NOT NULL;
```

이 한 줄 덕분에 앱을 열 번 열어도 같은 날 회차는 한 번만 생긴다. 놓친 회차를 휴지통으로 보내도 다시 안 생기는 것도 같은 이유다. 휴지통에 있어도 그 날짜 칸은 "이미 있음"으로 남아 있기 때문이다.

### 4-2. 고치는 요청에 기본값을 넣으면 생기는 사고

할 일을 고칠 때는 바꾼 칸만 서버로 보낸다. 체크하면 `{ completed: true }` 하나만 간다. 그런데 서버의 입력 검사에 이렇게 적혀 있었다.

```js
// 고치기 전 — 값이 안 오면 0, 값이 안 오면 빈 목록이 들어간다
const priority = z.coerce.number().int().min(0).max(3).default(0);
const tagIds = z.array(z.coerce.number().int().positive()).max(20).default([]);
```

카페에서 "아이스로만 바꿔 주세요"라고 했는데, 주문서에 사이즈 칸이 비어 있다고 **기본값인 작은 컵으로 바꿔 버린** 셈이다. 고치는 요청에서 빈칸은 "그대로 둬"라는 뜻인데, 기본값이 그걸 "0으로 바꿔"로 바꿨다.

```js
// 고친 뒤 — 고치는 요청에서는 기본값 없이 "없으면 그대로"
priority: priorityField.optional(),
tag_ids: tagIdsField.optional(),
```

새로 **만들 때**의 빈칸은 "기본값으로 채워"이고, **고칠 때**의 빈칸은 "건드리지 마"다. 이 버그는 둘을 같은 규칙으로 검사해서 생겼다.

### 4-3. `127.0.0.1`에만 연다

```js
// 반드시 루프백에만 바인딩한다. 0.0.0.0으로 열면 같은 네트워크의 다른 기기가 내 할 일을 본다.
const HOST = process.env.HOST ?? '127.0.0.1';
```

`127.0.0.1`은 "이 컴퓨터 자신"을 가리키는 주소다. 집 안 인터폰처럼 집 안에서만 울린다. 대문 초인종(`0.0.0.0`)으로 열어 두면 같은 와이파이에 붙은 누구나 누를 수 있다. 로그인이 없는 앱이라 이 한 줄이 사실상 자물쇠다. 그래서 휴대폰으로는 이 앱이 안 열린다. 일부러 그렇게 만든 것이다.

## 5. 막혔던 점과 해결

| 막힌 지점 | 원인 | 해결 방법 |
| --- | --- | --- |
| 완료 체크만 해도 중요도와 태그가 지워짐 | 고치는 요청의 빈칸을 입력 검사가 기본값(0, 빈 목록)으로 채움 | 고치는 요청에서는 기본값을 빼고, 같은 상황을 재현하는 테스트 추가 (4-2) |
| 태그를 만들면 화면에 `null` 글자가 찍힘 | 빈자리를 비워 두는 대신 `null`을 넘겼더니 글자로 들어감 | 넣을 것만 목록으로 모아서 넘김 |
| "매주"를 골라도 "매월 N일" 칸이 계속 보임 | 줄을 맞추려고 준 스타일이 "숨김" 표시를 이김 | 숨김 표시가 항상 이기도록 규칙 한 줄 추가 |

| 출석 체크 카드가 한 달 동안 빨갛게 쌓임 | 지난 반복 회차를 일회성 할 일처럼 "기한 지남"으로 보여 줌 | 맨 아래 한 줄로 접고 한 번에 휴지통으로 보내기 |
