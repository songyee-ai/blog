## 무엇을 만들었나

> 만성질환이나 노령기를 지나는 반려동물의 하루를 다섯 번 눌러 남기고, 홈에서 이번 주가 어땠는지 보는 앱. 처음엔 탭 네 개·작업 단위 33개로 크게 설계했다가, 기반을 만들어 본 뒤 '한 흐름이 끝까지 굴러가는' 화면 일곱 개로 다시 잡아 완성했다.

8회차 메인 퀘스트 — **나만의 프로덕트 {% include term.html name="MVP" %} 만들기**의 결과물이다. 무엇을 만들지는 그날 수업에서 정했다. 어제 저녁 약을 내가 먹였는지 기억나지 않고, 2주 전보다 밥을 덜 먹는지 알 수 없고, 병원에서는 "요즘 좀 안 좋아요"밖에 말하지 못하는 보호자의 하루에서 출발했다.

앞의 작업물들은 한두 세션 안에 끝나는 크기였다. 이번에는 처음으로 **문서를 먼저 쓰고, 일을 작은 단위로 쪼개, 여러 날 여러 세션에 걸쳐** 만들었다. 그리고 그렇게 크게 잡은 설계를 **스스로 줄여서** 완성했다. 이 글의 절반은 그 "줄이기" 이야기다.

계정도 설치도 필요 없다. 열면 바로 시작하고, 기록은 그 브라우저에만 남는다.

**직접 해보기** → [mgds-mvp-lite.vercel.app](https://mgds-mvp-lite.vercel.app)

**코드 보기** → [github.com/songyee-ai/mgds_mvp_lite](https://github.com/songyee-ai/mgds_mvp_lite)

### 일부러 넣지 않은 것

이 앱에는 흔한 기능 몇 가지가 없다. 빠뜨린 게 아니라 넣지 않기로 했다.

| 없는 것 | 이유 |
| --- | --- |
| 연속 기록 일수(스트릭) | 하루 빠뜨린 게 실패로 보이면, 힘든 날일수록 앱을 열지 않게 된다 |
| 빨간색 경고 | 팔레트에 빨강이 아예 없다. 쓰려 해도 쓸 색이 없다 |
| "어제 기록이 비어있어요" | 지적하지 않는다. 할 일은 **행동 버튼**으로만 말한다("10초면 돼요") |
| 힘든 날 개수 | 좋은 날만 센다. 힘든 날은 세는 대신 고맙다고 말한다 |
| 남은 날·카운트다운 | 매일 하나씩 **올라가는** 숫자만 있다(함께한 N일) |

학교 출석부를 떠올리면 쉽다. 결석한 날에 빨간 줄을 긋는 출석부는 결석이 하루 이틀 쌓이면 펼치기 싫어진다. 이 앱은 **출석한 날에만 도장을 찍는 도장판**에 가깝다. 실제로는 "기록을 빠뜨리는 것"이 아니라 "힘든 날에 앱을 덮는 것"이 데이터를 망치기 때문에, 화면에서 압박이 될 만한 것을 전부 걷어냈다.

## 1. 만들기 전 스케치

### 처음 설계 — 크게

처음 설계는 탭 네 개(오늘·흐름·병원·아이)짜리였다. 하루 기록에 더해 약 관리와 알림, 흐름 차트, 병원에 들고 갈 진료 요약서, 가족이 함께 쓰는 공동 기록까지 들어 있었다. 이걸 **작업 단위 33개**로 쪼갰다. 쪼개는 방식은 [8회차 리뷰]({{ site.baseurl }}/2026/09/08/mvp-scope-five-steps/)에 정리해 두었다.

그중 **앞쪽 11개 단위**를 이틀에 걸쳐 만들었다. 데이터를 저장하는 층({% include term.html name="스키마" %}·저장소), 날짜와 약 스케줄을 계산하는 함수, 하루 기록 카드, 백업, 아이 등록, 홈 화면까지다.

### 다시 잡은 설계 — 한 흐름만

11개를 만들고 나서 보니, 기반은 거의 다 있는데 **사용자가 처음부터 끝까지 써 볼 수 있는 흐름은 아직 없었다.** 탭 세 개는 비어 있었고, 33개 중 22개가 남아 있었다. 게다가 세션마다 문서를 다시 읽고 시작하다 보니 **단계를 거듭할수록 토큰 소모가 빨라졌다**([8회차 리뷰]({{ site.baseurl }}/2026/09/08/mvp-scope-five-steps/) 2-5). 이대로 22개를 더 가면 매일 쓸 수 있는 지점이 너무 멀었다. 8회차에서 배운 말 그대로 "다 만들려 하지 말고, 한 흐름이 끝까지 굴러가게"로 범위를 다시 잡았다.

{% include figure.html src="/assets/images/more-good-days-lite/flow.svg" alt="화면 흐름. 처음 한 번은 인트로 3장, 아이 등록, 준비됐어요 화면을 지난다. 그다음부터 매일은 홈과 기록 카드 5장을 오간다. 홈에서 기록 버튼을 누르면 카드로 가고, 다섯 번 누르면 홈으로 돌아온다. 가끔은 홈에서 아이 정보 고치기와 백업 내보내기로 간다" caption="그림 1. 다시 잡은 설계 — 처음 한 번, 매일, 가끔" %}

살린 것은 **등록 → 매일 기록 → 홈에서 돌아보기** 하나의 고리다. 약 관리·알림·흐름 차트·요약서·계정은 전부 뺐다. 이미 만든 데이터 층과 계산 함수는 그대로 가져다 썼으니, 줄였다기보다 **이미 단단히 다져 둔 바닥 위에 지붕 하나만 얹은 집**에 가깝다.

## 2. 만드는 과정 — 프롬프트 기록

### 시도 1 — 큰 설계를 단위로 쪼개 하나씩

첫 이틀은 단위 하나를 세션 하나에 맡겼다. 세션을 시작할 때마다 같은 틀의 요청을 넣었다.

- 단위 명세에서 **이번 단위 절과 상태 파일만** 읽을 것
- 그 단위의 **산출물만** 만들고 "하지 않을 것"은 건드리지 말 것
- 명세서와 다르게 해야 하면 **먼저 이유를 말하고 확인받을 것**
- 미결정 항목은 임의로 정하지 말고 물어볼 것
- 끝나면 상태 파일을 고쳐 다음 세션에 넘길 것

한 세션이 끝나면 다음 세션은 아무것도 기억하지 못한다. 그래서 **상태 파일 하나가 다음 세션의 입구**가 되게 했다. 이 파일은 단위마다 길어져서, 나중에는 대화가 길어져 요약될 때 내용이 뭉개질 수 있다는 걱정이 생겼다({% include term.html name="맥락 부패" %}). 그래서 "지금 지켜야 할 규칙"과 "왜 그렇게 됐는지(기록)"를 두 파일로 나눴다.

이 방식에서 가장 쓸모 있었던 건 **"명세서와 다르면 먼저 말하라"**는 한 줄이었다. 예를 들어 사진 처리 단위에서 명세서가 "품질 0.8로 줄인다"와 "300KB 이하여야 한다"를 동시에 요구했는데, 실제로 재 보니 둘이 부딪히는 사진이 있었다. Claude가 그걸 측정 결과와 함께 먼저 물어 와서, 내가 "0.8로 먼저 해 보고 넘으면 한 단계씩 낮춘다"로 정했다.

### 시도 2 — "2시간 안에 끝나는 MVP로 다시 잡아 줘"

11개 단위가 끝난 다음 날, 새 세션에서 이렇게 요청했다.

> … 최대 2시간 내 추가 단계만 거치면 마무리 가능한 라이트 버전의 mvp를 제안해줘

등록과 하루 기록만 살리고 나머지 탭은 빼되, 인트로와 마무리 화면을 붙이자는 생각이었다. 그리고 **원래 설계는 나중에 이어 할 거니 건드리지 말라**고 했다.

Claude는 먼저 지금 상태를 진단했다(33개 중 11개, 동작하는 화면 4개, 빈 탭 3개). 그리고 내 안을 세 군데 고쳐 제안했다.

- **홈은 살려야 한다** — 빼면 입력만 하고 아무것도 돌려받지 못하는 앱이 된다
- 응급실 카드는 아직 동작하지 않으니 지운다
- 온보딩 질문(어떤 마음으로 오셨어요 등)이 2시간 예산에서 유일하게 불확실한 부분이라 뺀다

확정안은 화면 여섯 개짜리 한 흐름이었다. 원래 저장소를 복사해 새 저장소에서 시작했고, 이어서 이렇게 덧붙였다.

> 라이트해진만큼 보여지는 문구나 컨셉 리드미를 마무리에 신경써보자.

기능이 줄어든 만큼 **"왜 이것만 있는지"**를 README에서 말하게 했다. 위의 "일부러 넣지 않은 것" 표가 그때 나왔다.

### 시도 3 — 인트로 그림: 결국 내가 직접 만들었다

배포하고 열어 보니 인트로 문구 위가 비어 있었다. 원래 설계에서 일러스트를 범위 밖에 둬서 자리만 잡혀 있던 것이다. 여기서 왕복이 가장 많았다.

1. Claude가 SVG를 직접 그려 넣었다
2. 내가 쓴 그림 가이드를 줬더니 다시 그렸는데, 결과가 마음에 들지 않았다
   > 1번 전혀 보호자 다리로 안보이고, 2번은 아예 싹다 뜯어고쳐야 할거 같은 느낌이야.
3. 원하는 느낌의 참고 이미지를 가져가자, Claude가 **이 그림은 손으로 코딩한 SVG로는 재현할 수 없다**고 답했다. 그라데이션 가득한 그림은 도형 코드로 그릴 수 있는 종류가 아니었다
4. 그래서 **이미지를 내가 만들고, Claude는 규격(크기·형식·안전 영역)만** 알려 주기로 했다. 결국 짧은 영상 세 개를 만들어 넣었다

영상이 들어간 뒤에도 모바일에서 1장이 비고 2·3장이 멈춰 있었다. 원인을 몇 개 고친 끝에, 내 아이폰에 **「동작 줄이기」가 켜져 있던 것**도 이유였다는 걸 알았다. 이 설정을 켠 사람에게는 영상을 아예 받지 않고 정지 그림만 보여 주게 바꿨다 — 움직임을 줄여 달라고 한 사람에게 움직이는 그림을 내려받게 할 이유가 없다.

### 시도 4 — 로고 자리는 시안을 보고 골랐다

직접 만든 로고를 화면 위에 두고 싶다고 하자, Claude가 먼저 화면별 시안을 만들어 보여 줬다. 크기와 간격을 정하고, 「건너뛰기」 버튼 위치는 시안 네 개 중에 골랐다.

> 나는 C가 마음에 들어. 그대로 진행시켜줘.

말로만 주고받았으면 몇 번 더 고쳤을 것이다. **그림으로 먼저 보고 고르는 것**이 훨씬 빨랐다.

### 그 사이 — 아이폰에서만 드러난 것들

데스크톱 브라우저에서는 멀쩡했는데 실제 아이폰에서 써 보니 문제가 나왔다. 이 대목에서 배운 게 가장 많다.

**기록할 때마다 백업 파일이 내려받아졌다.** 원래 설계는 "첫 기록 직후 백업 파일을 자동으로 만든다"였다. 브라우저 저장소가 지워질 때를 대비한 안전장치였다. 그런데 태그나 메모를 고칠 때마다 저장이 다시 일어나면서 그 자동 백업이 **여러 번** 돌았고, 그때마다 다운로드 창이 떴다.

> 원초적으로 바로 다운받게 하는거 없앨 수 없어? 굉장히 불편해.

자동 백업을 통째로 지우고, **사용자가 누를 때만** 파일을 만들게 바꿨다. 근거는 두 가지였다. 홈 화면에 추가한 웹앱은 브라우저가 저장소를 지우는 규칙에서 빠지고, **기록이 불편해지면 기록을 안 하게 된다.** 안전장치가 본래 목적을 해치면 안전장치가 아니다. 원래 설계와 다른 결정이라 상태 파일에 따로 표시해 두었다.

**홈 화면 아이콘이 「M」 글자로 바뀌었다.** Claude가 원인을 세 번 연달아 다르게 짚었고(아이콘 크기 표기, 주소 캐시, 투명 배경), 세 번 다 아니었다. 그 사이 나는 사파리 데이터를 지우기까지 했다. 그래서 강하게 말했다.

> 추측하지말고 제대로 판단하고 … 너가 직접 판단해.

그제야 **잘 되던 시점의 코드와 대조**하는 방식으로 바꿨고, 아이콘은 그 사이 한 번도 바뀐 적이 없다는 게 확인됐다. 진짜 원인은 코드가 아니라 **배포 서비스(Vercel)의 공격 방어 기능(Attack Challenge Mode)**이었다. 아이폰이 아이콘을 가지러 오면 그림 대신 확인용 안내 페이지를 돌려주고 있었다. 그 기능이 꺼진 뒤에는 아이콘 주소가 정상으로 응답했다. 이 일 뒤로 "잘 되던 때와 비교해 확정한 다음 고친다", "데이터를 지우라고 하기 전에 백업부터 안내한다"를 규칙으로 남겼다.

그 밖에 아이폰에서 날짜 입력칸이 카드 밖으로 튀어나오고, 고른 사진이 등록되지 않는 문제도 실기기에서만 보였다. 둘 다 고쳤다.

### 마지막 — 외부 자동 평가를 받아 따져 봤다

코드를 자동으로 평가해 주는 서비스에서 피드백을 받아, 받아들일 것과 아닌 것을 같이 따져 보자고 했다. 지적 중 두 개는 사실이 아니었다(없는 파일 중복, 개발 화면 노출). 대신 따져 보는 과정에서 **진짜 구멍 하나**를 찾았다.

기록에서 "구토", "헐떡임" 같은 태그를 고르면 병원에 전화할 수 있는 칸이 뜨게 만들어 두었는데, **병원 정보를 입력하는 곳이 화면 어디에도 없었다.** 개발용 시험 데이터에만 병원이 있었다. 실제 사용자에게는 이 기능이 영영 나타나지 않는 상태였다. 아이 등록 화면에 병원 이름·전화번호 두 칸을 더해 해결했다.

이후 아이 정보를 고치는 화면, 홈 화면에 추가하라는 권유 카드, 오프라인에서도 열리게 하는 서비스 워커를 붙여 마무리했다.

## 4. 코드에서 배운 부분

### 4-1. 빨간색을 "안 쓰는" 게 아니라 "쓸 수 없게" 만들기

설명을 위해 주석을 달았다.

```typescript
// 주간 점 하나의 모양. 'red' 가 없다.
export type Dot = 'filled' | 'empty' | 'gray' | 'none'
```

"빨간 점을 쓰지 말자"를 회의록에 적어 두면, 몇 달 뒤 누군가 무심코 빨간 점을 그린다. 그래서 **점의 종류를 정하는 타입 자체에 빨강을 넣지 않았다.** 코드에서 `'red'`를 쓰는 순간 TypeScript가 컴파일을 멈춘다. 색깔 팔레트(디자인 토큰)에도 빨강이 없고, 빨간 계열 색을 찾아내는 검사도 따로 돈다.

연필깎이 대신 **날이 없는 가위를 주는 것**과 비슷하다. "조심해서 써"라고 말하는 대신, 다칠 수 있는 부분을 처음부터 없앤다. 실제로는 원칙을 사람의 기억이 아니라 **타입·검사 같은 기계가 지키게** 하는 방법이다.

### 4-2. 다섯 번째 탭이 곧 저장

타입 표기를 줄이고 `// 다음 장으로` 주석을 더했다. 실제 코드는 저장소의 `DailyLogScreen.tsx` 에 있다.

```typescript
const choose = (card, value) => {
  const next = { ...draft, [card.field]: value }
  setDraft(next)
  if (step + 1 < CARDS.length) {
    setStep(step + 1)      // 다음 장으로
    return
  }
  // 마지막 카드의 탭이 곧 저장입니다. 별도의 저장 버튼이 없습니다.
  setDone(true)
  void persist(next, tags, memo)
}
```

"하루 10초"를 약속하려면 누르는 횟수를 줄여야 했다. 카드마다 "다음" 버튼이 있으면 열 번, 마지막에 "저장" 버튼까지 있으면 열한 번이다. 그래서 **선택지를 누르는 것 자체가 "다음"**이고, 다섯 번째 카드에서 고르는 순간이 저장이다. 태그와 메모처럼 매일 필요하지 않은 것은 저장 **뒤** 화면으로 뺐다. 탭 수가 다섯을 넘지 않는지는 테스트가 확인한다.

### 4-3. 일부러 망가뜨려 보기

테스트가 통과했다고 테스트가 제 역할을 한다는 뜻은 아니다. 아무것도 검사하지 않는 테스트도 늘 통과한다. 그래서 단위마다 **코드를 일부러 한 줄 망가뜨리고, 테스트가 실제로 실패하는지** 확인했다.

예를 들어 홈의 점을 그리는 코드에서 "아직 기록 안 한 날 → 미기록 점"을 "→ 회색 점"으로 한 단어만 바꿔 봤다. 화면만 보면 알아채기 어렵지만, 그러면 **아직 하지 않은 일을 "힘들었던 날"로 보여 주게** 된다. 테스트가 바로 실패하는 것을 확인하고 되돌렸다.

화재경보기를 달고 끝내는 게 아니라 **연기를 한 번 피워 보고 울리는지 확인하는 것**이다. 지금 이 저장소에는 테스트 397건과 원칙 검사 6종(금지 표현, 빨간색, 힘든 날 집계 금지 등)이 있고, 코드를 올릴 때마다 GitHub에서 자동으로 다시 돈다.

## 5. 막혔던 점과 해결

| 막힌 지점 | 원인 | 해결 방법 |
| --- | --- | --- |
| 인트로 그림을 원하는 느낌으로 못 그림 | 그라데이션 가득한 그림은 손으로 쓴 SVG 코드로 재현할 수 없음 | 이미지·영상은 내가 직접 만들고, Claude는 규격만 안내 |
| 모바일에서 인트로 1장이 비고 2·3장이 멈춤 | 아이폰이 자동 재생을 막음 + 내 폰에 「동작 줄이기」가 켜져 있었음 | 정지 그림을 먼저 깔고, 동작 줄이기를 켠 사람에게는 영상을 받지 않음 |
| 기록할 때마다 백업 파일이 내려받아짐 | 태그·메모를 고칠 때마다 저장이 다시 돌며 자동 백업이 여러 번 실행됨 | 자동 백업을 없애고 "누를 때만"으로 |
| 아이폰 홈 화면 아이콘이 「M」으로 바뀜 | 코드가 아니라 배포 서비스의 공격 방어 기능(Attack Challenge Mode)이 아이콘 대신 안내 페이지를 줌. 원인을 세 번 추측으로 헛짚음 | 잘 되던 때와 대조해 원인을 확정. 그 기능이 꺼진 뒤 정상 응답 |
| 아이폰에서 날짜 칸이 카드 밖으로 튀어나옴 | 아이폰 기본 입력칸 모양 | 기본 모양을 끄고 직접 스타일 지정 |
| 고른 사진이 등록되지 않음 | 브라우저가 지원하지 않는 형식을 **조용히** 다른 형식으로 바꿔 줌 | 결과 형식을 확인하고, 안 되면 JPEG로 저장 |
| 병원 연락 칸이 실사용자에게는 영영 안 뜸 | 병원을 입력하는 화면이 없고 시험 데이터에만 있었음 | 아이 등록 화면에 병원 두 칸 추가 |
| 오프라인에서 흰 화면 | 서비스 워커가 저장해 둔 파일과 실제 요청이 캐시에서 어긋남 | 캐시를 찾을 때 그 차이를 무시하도록 |
