## 1. 만들기 전 스케치

재료는 세 가지였다. GPT로 미리 만들어 둔 **캐릭터 이미지**(꽃무늬 셔츠를 입고 두 발로 선 흰 개), 자세를 뽑아 올 **포즈 참조 사진 두 장**, 그리고 수업에서 받은 **FLUX.2-klein 4B 예제 노트의 사본**.

{% include figure.html src="/assets/images/pose-image-tool/char.png" alt="노란 꽃무늬 셔츠를 입고 뒷다리로 선 흰 개" caption="그림 1. 캐릭터 레퍼런스 — 이 개가 사람 자세를 따라 하게 만든다" width="30%" %}

과제가 원한 흐름은 이랬다. 사람 사진에서 **OpenPose**가 관절을 뽑고, 그 관절 정보를 **ControlNet**에 조건으로 넣어, 프롬프트와 함께 이미지를 만든다. 결과는 "참조 사진과 같은 자세를 한 다른 인물"이어야 한다.

{% include figure.html src="/assets/images/pose-image-tool/pipeline.svg" alt="캐릭터 사진과 포즈 참조 사진, 프롬프트 세 입력. 포즈 사진은 OpenPose를 거쳐 스켈레톤이 되고, 캐릭터와 스켈레톤이 참조 이미지 조건으로 FLUX.2-klein-4B에 들어가 결과 이미지가 나온다. ControlNet 대신 참조 이미지 조건을 썼다는 설명이 붙어 있다" caption="그림 2. 실제로 만든 흐름 — ControlNet 자리에 참조 이미지 조건이 들어갔다" %}

## 2. 만드는 과정 — 프롬프트 기록

### 시도 1 — 과제 문서와 재료를 넘기고 "예제 없이 되는지" 묻기

클로드 코드에게 과제 설명 전문과 준비해 둔 폴더를 넘겼다. 요청은 짧았다.

- 예제 노트 사본과 이미지를 지정 폴더에 모아 뒀다. 캐릭터(`souse`)와 포즈 사진(`pose1`, `pose2`)은 이미 준비했다
- **예제 없이도 과제를 온전히 진행할 수 있으면, 지금 만든 재료로 함께 해 보고 싶다**
- 코랩에서 내가 무엇을 해야 하는지 알려 달라

클로드는 세 이미지를 먼저 열어 보고("포즈 대비가 뚜렷해서 조건 바꾸기 관찰용으로 좋다"), 셀을 짜기 전에 **먼저 짚을 사실 하나**를 꺼냈다.

> FLUX.2-klein-4B용 OpenPose ControlNet 가중치는 공개된 게 없습니다.

FLUX.2 계열 ControlNet은 32B짜리 `dev` 모델용이라 무료 T4에 안 올라간다. 대신 klein이 기본으로 지원하는 **참조 이미지 조건(`ReferenceLatent`)**으로 넣자고 했다. 관절을 뽑는 전처리는 ControlNet과 똑같이 하고, **조건을 넣는 통로만 바꾸는** 방법이다. 그리고 이 차이 때문에 포즈가 100% 고정되지는 않을 거라는 점도 미리 말해 줬다. 수업 자료에도 "FLUX.2는 아직 공식 ControlNet이 없다"고 적혀 있었으니, 과제의 벽을 첫 답변에서 만난 셈이다.

셀 원고는 파일로 받았다. 예제의 GPU 확인·설치·모델 받기 셀은 거의 그대로 쓰고, 설치 셀에 OpenPose 전처리기만 추가하고, 그 뒤로 포즈 추출 → 생성 → 실험 → 저장 셀을 새로 붙이는 구성이었다. **"테스트 못 한 코드"**라는 단서와, 멈춰서 보여 달라는 지점(포즈 추출 직후)도 함께 적혀 있었다.

### 그 사이 — 포즈 추출에서 멈추다

단계 7(포즈 추출)에서 오류가 났다. `OpenposePreprocessor`라는 노드를 찾을 수 없다는 메시지였다. 진단 셀을 돌려 보니 {% include term.html name="ComfyUI" %}의 확장 폴더에 GGUF 노드만 있고 **OpenPose 전처리기 폴더가 아예 없었다.**

원인은 나였다. 예제 사본의 설치 셀을 그대로 두고 그다음 단계부터 원고를 따라갔는데, 예제 설치 셀은 GGUF 노드만 받는다. 코드 문제가 아니라 **설치 누락**이었다. 빠진 노드를 설치하는 셀을 하나 추가하고 **서버를 다시 띄우니**(ComfyUI는 서버가 뜰 때 노드를 읽는다) 스켈레톤이 제대로 나왔다.

{% include figure.html src="/assets/images/pose-image-tool/pose1.png" alt="왼쪽은 머리 위로 양팔을 올려 하트를 만들고 한쪽 다리를 뒤로 든 사람의 보도 사진, 가운데는 OpenPose가 뽑은 관절 스켈레톤, 오른쪽은 흰 개가 머리 위 하트를 만들고 두 발로 선 결과" caption="그림 3. 포즈 1 — 하트는 따라왔고, 다리 들기는 무시됐다 (포즈 참조: 보도 사진, 출처 iMBC)" %}

첫 결과에서 머리 위 하트, 꽃무늬 셔츠, 두 발로 선 자세까지 따라왔다. 그런데 **스켈레톤에선 파란 다리가 뒤로 접혀 있는데, 결과의 개는 두 발 다 땅에 붙어 있었다.** 클로드는 이게 참조 이미지 조건의 한계를 보여 주는 증거라 마지막 관찰 셀에 그대로 쓰자고 했다. 그래프 제목의 한글이 네모로 깨져서 나눔고딕 폰트 셀도 하나 받았다.

### 시도 2 — 조건을 하나씩 바꿔 보기

과제 2단계는 조건을 바꿔 보며 무엇이 잘 따라오는지 관찰하는 것이었다. **시드를 42로 고정**해서, 바꾼 조건의 효과만 보이게 했다. 실험은 셋이었다.

| 실험 | 바꾼 것 | 결과 |
| --- | --- | --- |
| A | 같은 포즈, **프롬프트만** (햇빛 도심·실사 → 눈 오는 밤·3D 애니메이션) | **절반만.** 배경·조명·색감은 완전히 바뀌었는데 화풍은 여전히 실사 |
| B | 같은 프롬프트, **포즈 사진만** (포즈 1 → 포즈 2) | **가장 크게 달라짐.** 팔이 내려와 가슴 앞 손하트, 두 다리 딛기까지 |
| C | 스켈레톤 대신 **포즈 원본 사진**을 조건으로 | **거의 차이 없음.** 사진 속 사람이 섞여 들지도 않고 자세만 따라옴 |

{% include figure.html src="/assets/images/pose-image-tool/pose2.png" alt="왼쪽은 가슴 앞에서 손하트를 만들고 두 발로 선 사람의 보도 사진, 가운데는 스켈레톤, 오른쪽은 흰 개가 가슴 앞 손하트를 만들고 두 발로 선 결과" caption="그림 4. 실험 B — 포즈 사진만 바꿨더니 팔이 따라 내려왔다 (포즈 참조: 보도 사진, 출처 세계일보)" %}

{% include figure.html src="/assets/images/pose-image-tool/expA.png" alt="왼쪽은 햇빛 드는 도심에서 하트 포즈를 한 개, 오른쪽은 같은 포즈로 눈 오는 파스텔 거리에 선 개. 배경은 바뀌었지만 개는 여전히 실사 질감이다" caption="그림 5. 실험 A — 배경은 바뀌어도 화풍은 안 바뀌었다" %}

{% include figure.html src="/assets/images/pose-image-tool/expC.png" alt="왼쪽은 스켈레톤을 조건으로 만든 결과, 오른쪽은 포즈 원본 사진을 조건으로 만든 결과. 둘이 거의 같다" caption="그림 6. 실험 C — 스켈레톤을 넣으나 원본 사진을 넣으나 거의 같았다" %}

실험 C가 가장 뜻밖이었다. 이 파이프라인에서는 **OpenPose 전처리가 필수가 아니었다.** 모델이 참조 이미지를 그리는 도중에 직접 읽으니 사진에서도 자세를 스스로 알아낸 것이다. 그래도 스켈레톤을 쓰는 편이 안전하다고 적었다. 원본 사진을 넣으면 옷이나 배경 같은 불필요한 정보까지 같이 들어갈 위험이 있고, 스켈레톤은 조건을 **자세 하나로 좁혀 주기** 때문이다.

### 마무리 — 처음부터 끝까지 한 번 더

결과를 보고 클로드가 README와 `prompts.md`, 마지막 관찰 셀을 채워 줬다. 그리고 한 가지를 짚었다. 지금 노트는 **오류를 고쳐 가며 순서가 섞여서**, 처음 보는 사람이 위에서부터 실행하면 단계 7에서 나와 같은 오류를 만난다는 것. 그래서 두 가지를 옮겼다.

- OpenPose 설치 줄을 **설치 단계 셀 안으로**
- 한글 폰트 셀을 **첫 그래프를 그리기 전으로**

셀 순서를 정리하고 **처음부터 마지막까지 다시 실행**해서 다 잘되는 걸 확인했다. 오류 때 쓴 진단 셀은 지우지 않고 "(참고) 설치된 커스텀 노드 확인 — 단계 7에서 노드를 못 찾는다는 오류가 나면 여기부터 본다"라는 제목으로 남겼다. 처음 제목은 "왜 안 잡혔는지"라서, 없던 문제를 있는 것처럼 읽힐 수 있다는 지적을 받고 고쳤다.

### 시도 3 — GitHub에 웹으로 올리기

과제 안내대로 명령줄 없이 올렸다. 저장소를 Public으로 만들고 `uploading an existing file`에 **README, prompts.md, 노트, samples 폴더를 끌어다 놓았다.** 클로드가 미리 알려 준 함정이 하나 있었다. 업로드 페이지의 `choose your files`로는 **폴더를 고를 수 없어서**, 반드시 드래그해야 `samples/` 구조가 유지된다.

제출 주소도 하나 고쳤다. 처음 붙여 넣은 건 끝에 `.git`이 붙은 복제용 주소였고, 과제 제출란에는 `.git` 없는 저장소 주소를 넣어야 했다. 노트가 GitHub에서 노트 모양으로 렌더링되는지까지 확인하고 제출했다.

## 4. 코드에서 배운 부분

### 4-1. 그림 두 장에 역할을 붙여 준다

참조 이미지를 두 장 넣을 때 모델은 어느 쪽이 캐릭터이고 어느 쪽이 자세인지 모른다. 그래서 {% include term.html name="프롬프트" %}에 순서로 역할을 적었다.

```
The fluffy cream-white dog from the first reference image, ...
It takes exactly the body pose drawn by the stick-figure skeleton
in the second reference image: ...
```

"첫째 참조 = 이 개", "둘째 참조 = 이 막대 인형의 자세"라고 못 박으면 캐릭터와 포즈가 섞이지 않았다. 반 친구 둘에게 "너는 옷 입은 모습을, 너는 서 있는 자세를 보여 줘"라고 각자 맡기는 것과 같다.

### 4-2. 스켈레톤이 있어도 자세를 말로도 설명한다

참조 이미지 조건은 ControlNet처럼 픽셀 위치를 강제하지 않아서 **조건이 약하다.** 그래서 스켈레톤을 넣었어도 `both front paws raised high above the head forming a big heart shape`처럼 **자세를 문장으로도** 적었더니 결과를 실제로 끌어당겼다. 14회차 리뷰에서 정리한 "비워 둔 칸은 모델이 채운다"가 여기서도 그대로였다. 그림으로 준 조건이 약하면 말로 한 번 더 채워야 한다.

### 4-3. 시드를 고정해야 비교가 된다

세 실험 모두 {% include term.html name="시드" %} 42, 스텝 6, 가이던스 1.0, 1024×1024로 고정했다. 시드를 풀어 두면 결과가 달라졌을 때 **조건을 바꾼 탓인지 운인지** 가릴 수 없다. 한 번에 한 칸만 바꾸고 나머지는 모두 묶어 두는 것, 과학 시간의 콩나물 실험과 같은 원리다.

## 5. 막혔던 점과 해결

| 막힌 지점 | 원인 | 해결 방법 |
| --- | --- | --- |
| 과제가 요구한 ControlNet을 쓸 수 없음 | FLUX.2-klein-4B용 OpenPose ControlNet 가중치가 공개돼 있지 않음. FLUX.2 ControlNet은 32B `dev`용이라 T4에 안 올라감 | 모델이 기본 지원하는 **참조 이미지 조건(`ReferenceLatent`)**으로 스켈레톤을 넣음. 전처리는 같고 통로만 다름 |
| `Node 'OpenposePreprocessor' not found` | 예제 사본의 설치 셀을 그대로 써서 OpenPose 전처리기가 설치되지 않음 | 설치 셀 추가 → **서버 재시작** → 포즈 추출 재실행. 최종본에선 설치 줄을 설치 단계 안으로 옮김 |
| 한쪽 다리 들기가 두 번 다 무시됨 | 추정: ① 캐릭터 사진이 두 발로 선 모습이라 그쪽으로 끌림 ② 개 다리 구조가 사람 스켈레톤과 안 맞음 ③ 참조 조건은 관절 위치를 강제하지 않음 | 한계로 README와 관찰 셀에 기록 |
| "3D 애니메이션 스타일"이 거의 반영 안 됨 | 캐릭터 레퍼런스가 실사 사진이라 정체성 유지가 화풍 지시를 이김 | 한계로 기록. 배경·조명·색감은 프롬프트로 자유롭게 바뀜 |
| 그래프 제목 한글이 네모로 깨짐 | Colab 기본 글꼴에 한글이 없음 | 나눔고딕 설치 셀을 첫 그래프 앞에 둠 |
| 노트를 처음부터 돌리면 같은 오류가 날 뻔함 | 오류를 고치며 셀 순서가 섞임 | 셀 순서 정리 후 **처음부터 끝까지 재실행**으로 확인 |
